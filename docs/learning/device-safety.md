# 实验设备安全与恢复

## 数据边界

实验设备不使用日常主账号，不保存不可替代数据。聊天、照片、令牌、签名密钥和应用私有数据不进入研究日志或仓库。

ADB 报告、logcat 和框架日志默认保存在 `/tmp`。需要长期保留时先删除 serial、账号标识、文件路径中的用户名和业务内容。

## 变更前记录

- 设备型号、Android build fingerprint、安全补丁和 ABI。
- bootloader 解锁状态、当前 slot 和启动链状态。
- root 方案、Zygisk 实现、Vector 版本及每个模块版本。
- 原始 boot/init_boot 镜像的可信来源和 SHA-256。
- 可用的 fastboot、recovery 或厂商刷机路径。

## 恢复层级

1. 强制停止目标应用，停用本次实验模块。
2. 停用 Vector，验证系统能否正常启动。
3. 进入 root 管理器的安全模式或模块禁用机制。
4. 使用已验证的启动镜像恢复启动链。
5. 必要时使用 recovery/fastboot/厂商工具恢复完整系统。

具体按设备和 root 方案的官方流程执行。未验证第 3–5 层时，不 Hook `system_server`、SystemUI、Launcher 或启动关键服务。

## 恢复演练

在没有故障时完成一次演练：

- 停用一个无害测试模块。
- 重启并验证模块确实未加载。
- 恢复模块并验证作用域仍正确。
- 记录耗时、所需主机工具和失败分支。

演练只验证模块停用与恢复，不人为制造 bootloop。
