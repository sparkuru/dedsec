# 研究任务 Backlog

## R0：环境与基线

- `R0.1` 采集设备预检报告。
- `R0.2` 验证模块禁用与恢复路径。
- `R0.3` 在完整 Android 工具链构建 target app。
- `R0.4` 安装 target app，保存无模块基线日志与 APK SHA-256。

完成证据：设备报告、恢复记录、构建日志、APK 和基线日志能够相互对应。

## R1：Legacy API

- `R1.1` Hook 构造器与普通实例方法。
- `R1.2` Hook 重载、静态、final 和 synchronized 方法。
- `R1.3` 改写参数、返回值与异常。
- `R1.4` 验证主线程、后台线程与 `:worker` 进程。
- `R1.5` 验证错误包名、错误进程和错误 ClassLoader 的失败表现。

完成证据：每个行为有执行前预测和可重复日志；能够解释未生效的原因。

## R2：Modern API

- `R2.1` 使用 libxposed API 重做 R1 的最小集合。
- `R2.2` 固定 scope 与模块元数据。
- `R2.3` 建立模块 App 与 framework service 的最小通信。
- `R2.4` 比较 legacy 与 modern 回调链和错误处理。

完成证据：同一 target、同一输入下的结构性对照报告。

## R3：Vector 源码链路

- `R3.1` Zygisk 入口与进程筛选。
- `R3.2` 作用域配置的生产、存储和读取。
- `R3.3` 模块发现、ClassLoader 和入口分发。
- `R3.4` Hook 请求到 LSPlant 的映射。
- `R3.5` 日志、异常隔离和 daemon/service 通信。

完成证据：固定 commit 的源码锚点与一次运行日志共同支持调用图。

## R4：混淆与适配

- `R4.1` 创建 target app 的第二个结构版本。
- `R4.2` 比较类名、字符串和结构查询。
- `R4.3` 验证零候选、多候选和缓存失效。
- `R4.4` 建立版本化 resolver 报告格式。

完成证据：规则在两个结构版本上得到明确的成功或安全失败。
