# Xposed 模块能力与边界

## 框架行为

LSPosed-like 框架负责提供运行环境，而不是直接实现宿主功能：

1. 将框架代码注入选定进程。
2. 根据包、进程、用户和作用域选择模块。
3. 建立模块与宿主的 ClassLoader 边界。
4. 发现模块入口并分发生命周期事件。
5. 将 Java/native Hook 请求映射到底层 Hook 引擎。
6. 管理模块配置、日志、错误和框架通信。
7. 在目标进程结束或模块停用后撤销运行时影响。

## 模块可实现的能力

| 能力 | 典型动作 | 前提 |
|---|---|---|
| 改变方法行为 | 观察或替换参数、返回值、异常和调用顺序 | 找到正确方法与时机 |
| 使用宿主内部状态 | 读取对象、调用内部服务、复用已登录会话 | 代码运行在正确进程与 ClassLoader |
| 改变界面 | 插入控件、修改 Adapter、改变资源或生命周期 | UI 结构和资源方案兼容 |
| 适配混淆宿主 | 通过稳定类名、反射、结构特征或 DexKit 定位 | 候选可验证且版本化 |
| 与模块 App 通信 | 传输配置、任务、小型 DTO 或文件描述符 | 身份验证和协议版本明确 |
| Hook 系统行为 | 进入 system_server 或系统应用 | root/Zygisk、正确作用域和更高风险控制 |
| native 观测与改写 | 库加载回调、符号解析、inline hook | ABI、Android 版本和 native 引擎兼容 |

## 能力边界

- 注入目标进程不等于获得其他进程或服务端的数据。
- root 不会自然提供宿主内存中的会话对象、临时密钥或解码状态。
- 方法可以被 Hook 不代表调用点仍然存在；ART inline、AOT 和版本更新会改变结果。
- 读取到部分 UI 数据不代表取得完整业务数据集。
- 修改 APK 会改变签名与安装关系，可能破坏账号登录、跨应用调用和更新链。
- 资源 Hook、native hook 和系统进程 Hook 的兼容与故障半径高于普通应用 Java Hook。
- 隐藏文件名、堆栈或 root 痕迹只能减少部分检测面，不能证明不可检测。
- 宿主不支持、候选不唯一或完整性不可证明时，应返回明确的不支持或部分结果。

## 工具设计约束

发布项目需把以下层次分开：

```text
module entry
  -> process and scope guard
  -> host adapter
  -> normalized domain model
  -> task orchestration
  -> export or user interface
```

只有 host adapter 可以引用宿主私有类名、字段、反射和 DexKit 特征。业务层依赖稳定领域模型，不传播宿主对象。
