# 统一秘密库与公共认证技术设计初稿

状态 in_progress / 2026-10-10 最新完整规划已获批准；权威契约见 [App 统一秘密库](../../../design/app-authentication.md)，源需求见 [PRD](prd.md) 及 [SSH 父任务](../10-08-ssh-terminal/prd.md) R11/AC10。技术关卡仍需验证。

Android AppSecrets 拥有唯一便携库/KDF/加密写入/设备包装/库代次与内存会话；AppAuthentication 继续负责系统 UI、平台兼容、用途/请求绑定及 Keystore 受保护操作。两组件同属公共底座，系统的单流程授权不等于库解锁时长。Flutter 是类型化交互入口，不获得数据密钥。

统一库按 namespace/type/entryId 和资源身份存储条目，TOTP/SSH adapter 只使用各自受限操作。设备快捷材料绑定库材料代次，可经共同系统流程登记/解封/关闭；密码派生是主口令路径，不能被设备 Keystore-only 数据格式替代。v1 格式、AAD/nonce/参数上限已固定，见权威契约及新增 [宿主规范](../../spec/backend/app-secrets.md)；真实平台探针尚待运行。当前实现/实际检查与未完成关卡见 [check](check.md)，下文仍描述批准目标，不代表所有条款已实现验收。

SSH 只拥有身份绑定、host key gate 和 native 凭据通道，TOTP adapter 拥有条目/URI 参数/时间码与展示规则；均不重复实现秘密库或解锁 UI。统一库锁定清理秘密缓存/拒绝新操作，SSH 已建立 transport 继续遵守后台保留/Stop 契约。导入成功换代次后所有未完成旧秘密请求失效，不以此声称必然停止所有已建立远端会话。

统一会话规则已确认：前台跨业务共享，锁屏/手动锁/进程重启锁定，后台超时以用户选择秒数控制，默认 30、0 即锁。单调截止时间和代次由公共 owner 检查，超时回调不作为唯一有效性判断；回前台和秘密操作都检查期限，配置改变不重新开始旧后台计时或恢复已锁定库。具体规则只引用公共领域契约。

公共库新增类型化加密文件对象及 manifest，覆盖受管 SSH config/Include/私钥/公钥或证书/known_hosts 和凭据的完整一致快照；公共底座负责密文对象/事务，SSH adapter 验证引用语义及信任导入，迁移只映射逻辑路径，不复用源 FD/SAF 授权。没有单独的长期明文 SSH 目录副本；原私有目录表述改为逻辑受管结构。具体 runtime 内存/FD 视图由 SSH native 探针验证，底座不得通过普通磁盘明文 staging 来绕过要求。

2026-10-10 接口补齐：新增 native-only `SshBundleProposal`，有界深拷贝、规范摘要及关闭擦除，明确 ADD/REPLACE/DELETE 文件变更，替换/删除绑定旧对象摘要。`SshVaultAdapter.bundleRequest/commitBundle` 使用一次性 `SSH_BUNDLE_WRITE` 操作，绑定完整 proposal/快照/会话；独立 exact bundle approval 在请求与提交复核，默认拒绝，主机核验不替代批量信任审阅。候选完整 manifest 必须通过结构和 SSH validator 校验，包括删除最后一个 SSH 对象；无正式 validator 仍失败关闭。

此事务复用 `AppSecrets.commitManifest` 的加密/认证读回/原子记录及 beforeCommit，不新增 KDF/格式/持久 owner。只修改明确列出的文件，保留其他文件及全部无关条目；悬空引用、共享依赖破坏和有关联口令的私钥删除拒绝，不静默级联。首轮不新增关联凭据删除清单，未来需要时由明确 typed 事务扩展并单独验证。容量与公共格式一致：128 文件、单文件 1 MiB、文件总量 8 MiB、引用深度 8；超限完整拒绝，不截断配置语义。

恢复审阅合同另补齐：保留普通 `SshContentValidator`，新增注册版本化 `SshRestoreReviewer` 和默认拒绝的 `ExactRestoreApproval`。来源或已由本次目标口令认证的目标任一有 SSH，均要求不可变有界审阅（包括 TOTP 包覆盖现有 SSH）；公共核心校验来源/目标全部 SSH 对象的 coverage，并将快照摘要、providerId/semanticVersion/registration revision 与完整投影合成 reviewBinding。投影列明来源/目标信任条目、冲突/变化/删除/无法映射，不解析 known_hosts 或私钥原文到 UI。审阅超限/不完整拒绝，不截断风险。

ImportPreview 持有同一已认证 source、target binding 和审阅快照；目标 manifest 仅供短期 reviewer 使用后擦除。提交确认必须匹配 previewId+reviewBinding+provider revision/epoch/deadline，一次 host consent receipt 再经审批 gate；最终存储效果边界复核这些绑定。旧 TOTP-only 提交可保持兼容，混合恢复缺显式绑定/正式 reviewer+approval+validator 时继续拒绝。真实语义和信任 diff 实作归 SSH consumer；fixture review 只证明公共编排，不声明生产 mixed 恢复通过。

导出/覆盖/改口令用新输入口令派生密钥并认证解密对应当前代次或来源快照；框架管理未验证/认证成功/内容合规/确认/提交状态，前端布尔值不能授权。来源认证失败统一提示口令错误或文件损坏，认证完成前不消费明文；来源通过仍不自动授予 SSH 主机信任。目标覆盖额外验证当前口令，空目标只需来源口令，一次管理授权绑定来源摘要/目标代次/操作并在效果边界复核，锁定/取消/换代失效。完整规则及验收只引用公共领域契约。

2026-10-10 文件导出追加决定：目标同名明确提示是否覆盖，失败清理本次部分，保护原文件。采用所选目录本次使用（无持久 tree grant）的有界同名核验、随机独立 stage 写入/close/完整密文读回、绑定目标的覆盖确认。覆盖时旧文档只改到随机 rollback 名，最终名字通过 createDocument 创建新文档/新 ID，禁止对既有 URI 打开写流；返回改名/旧 ID/新碰撞均中止。失败只删精确 ledger 中本次创建的对象，恢复旧名遇到其他文件则保留 rollback 并反馈位置，不覆盖竞争文件。final 已验证后的旧文档删除属于提交后清理，失败保留新 final 并准确报告旧残留，不回滚删掉唯一新备份。

provider 调用错误不证明没有效果，删除/恢复失败显示真实角色与位置，不承诺任意 provider 的多文档原子事务。能力不足时拒绝覆盖，保留另存新文件路径。记录精确角色/ID/URI 返回链及操作阶段；私有恢复记录只含最小元数据、无主口令/明文库，重启不自动访问/扫描目录，需用户重新授权同目录才能恢复。实作依据及故障矩阵见 [export transaction 研究](research/export-transaction-plan.md)。

更换主口令为首版公共设置功能：旧口令认证当前快照，新口令确认后构建完整新加密代次，验证读回/内容一致后原子切换；提交前失败保留旧库/包装，提交后旧包装不再有效。快捷重登记失败保留新库并用新口令恢复，不回滚已完成切换；崩溃恢复要求完整旧或新代次，不混合。TOTP/SSH adapter 的条目和文件身份内容不变，旧备份继续用旧口令。

关闭快捷方式复用管理操作的当前口令真实认证解密，授权另绑定设备材料版本。停用持久化后撤销库会话/快捷请求并清理设备材料，数据保留；提交前错误/取消不改变原状态，提交后清理失败保持停用，不能复活旧材料。具体 BASE-12 及中断恢复只引用公共领域契约。

敏感页面保护已批准（BASE-13）：公共 Android 窗口协调器结合 Flutter 路由/对话框 owner 生命周期，保护完成后才呈现秘密，移除秘密后才撤销本模块标记，不清其他 owner；公共口令 UI、TOTP 及 SSH 凭据 UI 共用，后台宽限仍隐藏任务预览。覆盖前后台/嵌套/迟到/系统 UI 切换，并以目标平台实测记录支持范围，剪贴板规则按独立批准的 BASE-14 执行。

BASE-14 已于 2026-10-10 收敛：ctOS 只在有效会话内响应用户主动复制当前 TOTP，helper 附敏感标记。用户自行管理已复制内容；移除自动清理、清理时长、复制 ID/跟踪/读取/监听/定时器/补清及相关探针。后台库会话超时保持 BASE-08，不受此决定影响。

公共 UI 路由/设置已确认（BASE-15）：工作台独立验证器页面，验证器/SSH 导向唯一秘密库设置，主口令/快捷/后台解锁时间/备份集中管理。首次设置/导入/解锁带原业务返回上下文，取消无半成品；路由不代表授权，不停止已建立 SSH 或阻塞普通页面。设置与公共底座可通过受限测试入口独立验收，不依赖 SSH 客户端完成。

先验证密码文件/文件对象事务和两受限消费者，再验证 API 28/29 与 30+ 系统认证/Keystore，再由业务接入。管理操作再次手动输入及真实认证解密、首版更换主口令、关闭快捷方式本次口令认证解密和入口规则已确认；用户已撤销 HOTP 与验证码清理，底座实施进行中。遇到平台/产品不满足回规划，不降级免验证，不更改 Root/HFTP；导出同名确认/失败精确清理已获用户决定，事务及真实 provider 关卡仍待验证。

公共底座先独立验收后供 TOTP/SSH 分别接入，TOTP 不是 SSH 的依赖；native 文件读取可行性探针宜在接口冻结前尽早验证，客户端完整集成依赖公共底座。HOTP 专用 schema/计数事务及恢复/校准能力均不包含。
