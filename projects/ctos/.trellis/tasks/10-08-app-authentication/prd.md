## Goal

形成一个主口令、一个可移植加密秘密库、一套可选设备快捷解锁和迁移流程，供 Authenticator 与 SSH 复用，减少不同实现的理解/维护成本。源需求仍承接 [SSH 父任务](../10-08-ssh-terminal/prd.md) R11 / AC10，统一契约权威入口为 [App 秘密库与公共认证](../../../design/app-authentication.md)。

## Requirements
- BASE-01：统一首次设置/导入、主口令派生、认证加密文件、内存库会话、设备快捷解锁的开启/关闭、加密导出/确认覆盖；主口令与明文库不落盘，源口令可在新设备恢复，不依赖原设备 Keystore。
- BASE-02：保存类型化/分命名空间的 TOTP 种子和用户主动保存的 SSH 密码/私钥口令；业务 adapter 逐次绑定用途/条目/目标，不提供任意秘密枚举或向 Flutter 返回数据密钥。
- BASE-03：独立的系统认证接口统一可用性、用途/目标/请求绑定、并发、取消、生命周期及错误；认证绑定 Keystore 密码操作，不返回全局已认证布尔值。原系统流程的有限期限不替代统一库会话策略。
- BASE-04：服务复用同一库与认证实现；需要新解锁由前台承接，后台返回 foreground_required。AppAuthentication 的短期授权与 AppSecrets 库会话分别管理，旧库/旧调用方回调不复用。
- BASE-05：导入先完整验证/预览，再明确覆盖并原子提交；失败/取消保留旧库及快捷材料；成功后旧会话/快捷材料失效，新设备重新登记。不自动合并，不导出系统/Keystore 解锁材料。
- BASE-06：不导出跨 App API，不更改 Root 权限；SAF 仅使用用户本次明确选取授权，不扩大无关用途或新增广泛存储权限/持久 grant。不批量给 HFTP/信息/终端等无关功能增加验证；普通页面不因新库被全 App 登录墙阻挡。
- BASE-07：此前 SSH 的设备-only 凭据加密/不迁移方案由统一主口令库替代；SSH 仍控制用户主动保存、目标绑定、host key 核验及受管 native 通道。
- BASE-08：2026-10-09 用户确认前台跨页面/业务共享解锁会话；锁屏/手动锁立即锁，进程重启锁定；后台保留时间按用户选择的非负整数秒，默认 30、0 表示立即锁定。TOTP/SSH 共用一个设置，不因切换功能重复询问同一库口令；业务目标检查仍逐次执行。
- BASE-09：2026-10-09 用户确认 SSH config、Include、私钥及关联公钥/证书、主机信任记录与库内凭据一起加密保护/备份恢复。公共库持有类型化文件对象/逻辑引用和加密事务，SSH adapter 校验语义/闭包/信任，不能只加密备份而长期留明文受管私钥。来源必须是用户主动导入的受管内容，不自动扫描外部；外部原件不自动删除。
- BASE-10：导出/覆盖/改主口令必须重新手动输入主口令，并通过派生密钥及认证解密在公共宿主判定，不能用生物识别、已解锁会话或口令字符串比对替代。来源包完整认证后仍校验内容/引用/信任并预览确认；覆盖已有库还验证当前目标口令，空目标只验证来源。管理授权一次性绑定操作/来源快照/目标代次，实际提交再次检查，失败不修改旧库或设备材料。2026-10-10 用户追加文件导出规则：目标同名提示覆盖，本次导出失败删除本次创建的部分，保护原文件；采用先独立暂存/验证、确认后提交的流程，清理失败须明确反馈与恢复位置。具体状态与旧备份语义见公共权威契约。
- BASE-11：2026-10-09 用户确认首版包含更换主口令，公共秘密库设置拥有唯一入口；旧口令真实认证解密后，设置/确认新口令，对完整混合库及受管文件以新盐/密钥/nonce 重新加密、验证和原子提交。提交前失败/取消保留旧库/快捷材料；成功换代使旧会话/包装失效并允许重新登记。提交后登记失败仍可用新口令，历史备份继续用旧口令，TOTP 种子/SSH 远端密码/私钥自身口令不因此改变。
- BASE-12：2026-10-09 用户确认关闭本设备生物/系统锁屏快捷方式必须重新输入当前主口令并真实认证解密；生物/已有会话不代替。错误/取消/提交前失败保留原库/快捷状态，成功仅移除本设备公共包装/专属密钥并锁定库、拒绝旧快捷请求，TOTP/SSH 完整密文与主口令路径保留。停用先持久化再清理密钥，提交后清理失败仍保持停用，不影响 Android 登记/其他设备。
- BASE-13：2026-10-09 用户确认秘密库敏感页面禁止系统截图/录屏、隐藏最近任务预览，普通页面保留截图。公共宿主/Flutter 协调安全窗口生命周期，口令管理 UI 及 TOTP/SSH 敏感呈现复用同一机制；先保护再呈现，先移除秘密再释放本模块标记，不由嵌套/迟到回调误清其他敏感 owner。显示保护不代替解锁或业务授权，后台宽限不允许任务预览泄露。
- BASE-14：2026-10-10 用户撤销验证码剪贴板清理，清理由用户自行处理。公共宿主 helper 仅在用户主动复制时，经 TOTP adapter 检查有效条目/会话并生成当前时间码，再写入附敏感标记的 ClipData；不自动更新、不读取/监听/清空/跟踪剪贴板、不设置清理时间或复制 ID、不持久化代码、不修改普通输出复制。此决定取代旧默认 30 秒可调清理要求。
- BASE-15：工作台 Authenticator 与 TOTP/SSH 共同的“秘密库设置”入口保持确认；唯一管理主口令、快捷解锁、后台解锁保留秒数及加密导入导出，取消验证码清理时间。首次设置/导入/解锁由公共流程承接、完成回原业务，取消不留下半成品；入口/导航不替代实际授权，不停止已建立 SSH 或给普通页面增加登录墙。

## Acceptance Criteria

- [ ] 原父 AC10：两个消费者共用系统认证/受保护操作，成功/取消/不可用/锁定/并发/后台/销毁/迟到回调稳定且一次完成。
- [ ] 不同用途/目标/consumer/库代次不能错用授权；旧公共系统上下文不延长库会话，库锁定拒绝新秘密操作。
- [ ] 同一格式的混合 TOTP/SSH 秘密库可用同一主口令在另一安装环境恢复；错误口令/篡改/超限/取消不覆盖现有库，导入成功使旧设备材料失效。
- [ ] 快捷方式可跳过、启用、关闭；关闭保留库和主口令路径，设备认证失效不免验证或毁掉可移植密文。
- [ ] 两个 adapter 使用共同密钥/会话设施而只执行批准的业务操作；不存在另一个 SSH-only KDF/秘密库/解锁路径。
- [ ] API 28/29 与 30+ 系统认证及真实 Keystore 行为分开验证，不用 mock 声称实机通过。
- [ ] 已建立 SSH 会话不因秘密库锁定被主动断开；未完成/新凭据请求仍受锁定和 host key/身份检查。
- [ ] BASE-08：默认 30 秒及用户设置的 0/正整数按共享规则生效，重启保留设置但不恢复解锁；宽限内回前台免重输，到期/锁屏/手动锁需重新验证；两业务行为一致。后台执行暂停/迟到回调/系统时间变化不延长期限，调大秒数不能恢复已锁定会话，改短后立即检查原后台时刻。
- [ ] BASE-09：完整包在另一设备恢复配置/Include 引用、私钥身份、凭据关联及用户批准的信任；目标绝对路径/FD/SAF 授权不从源包复用。遍历/越界/重复/缺失引用/篡改/超限/取消均不覆盖旧状态，配置及密钥/信任以同代次提交，不执行导入配置或绕过指纹变化检查。锁定状态的受管持久数据和导出只有密文。
- [ ] BASE-09 恢复审阅：来源或已认证目标含 SSH 均展示完整审阅，包括纯 TOTP 覆盖目标 SSH；投影与双方快照/provider 注册版本/本次确认绑定。缺正式 provider、coverage 不全/超限、错误绑定、换版/撤销或过期均拒绝，不把空审阅当生产语义通过；不向 UI 暴露可猜测低熵口令的直接摘要。
- [ ] BASE-10：日常生物解锁后仍不能直接导出/覆盖/改口令；实际输入错误/正确口令分别认证失败/成功。来源口令与目标口令不同可验证后覆盖，空目标仅需来源口令；认证失败、截断/头部或内容篡改、schema/引用校验失败、取消/锁定、源快照替换或目标换代均拒绝提交并保留旧数据/快捷材料。不得消费认证完成前的流式明文字节或依赖 Flutter trusted 标记；格式有效但不合规内容也拒绝。首版改口令必须验证旧备份旧口令及新库新口令语义，失败不留半成品。
- [ ] BASE-10 文件导出：同名目标明确确认覆盖，确认前原文件内容不变；失败只清本次创建部分，旧对象不被截断或误删。新 final 验证后清旧失败仍保留新备份并显示残留；清理/恢复/身份不确定显示阶段及位置，不误报已清理。取消/超时/关闭和迟到缓存回执保持真实结果，重启恢复需本次重新授权；坏导出记录拒绝新导出但不阻塞正常库使用。实际 provider 行为与本地夹具结果分列。
- [ ] BASE-11：旧口令错误、新口令两次不一致、取消、重新加密/读回/提交前失败都保留旧有效库与快捷材料；成功后混合条目/文件内容与关联不变，新库用新口令，旧口令不能解密新库，旧备份仍用旧口令。旧会话/包装拒绝使用，重登记失败不损坏新库。写入/提交中断重启后只能恢复完整旧代次或完整新代次，不能出现半库/混合代次；改库口令不修改远端认证秘密。
- [ ] BASE-12：生物已解锁仍需新输入口令才能关闭；错误口令/取消不改变库/快捷状态，正确口令后两个业务均回主口令解锁，数据/文件关联不变，Android 登记/其他设备不变。并发快捷请求、迟到回调、材料重登记换版/库换代不能错用关闭授权；停用提交/清理中断重启后不复活旧快捷，清理失败保持停用及主口令恢复路径。
- [ ] BASE-13：验证码/口令输入等敏感页面在目标平台截图/录屏/最近任务中不显示秘密，普通页面截图恢复；首次设置/解锁/管理操作、嵌套对话框/路由替换/迟到回调、前后台/锁屏/SAF 返回的保护切换无秘密帧泄露。API 28/29、30+ 与 ROM 分别记实测和限制，不把 mock/设置标记当平台验证；不更改普通 Shell/SSH 输出复制规则或其他窗口 owner 的保护。
- [ ] BASE-14：有效会话内用户主动复制当前验证码，附敏感标记；取消/锁定或无效条目不得复制。代码刷新不改剪贴板，无读取/监听/清理/复制 ID/清理偏好或定时器，验证码不为清理落盘；不延长库会话或影响普通复制。清理由用户自行处理，无跨应用清理探针验收。
- [ ] BASE-15：工作台进入验证器，验证器/SSH 都进入同一设置页且显示同一库/快捷/后台保留设置，初始化/导入/解锁成功回原业务、取消无半成品。两业务设置变动一致，无验证码清理设置；导航不复活已锁库、不重复询问有效前台会话，管理操作仍需本次口令，已建立 SSH 不因导航被停止，普通页面保持可用。

## Scope and Dependencies

此 task 是两个业务 task 的先行共享底座，不依赖 SSH 客户端或 TOTP 页面代码；可用两个受限测试 adapter 独立验收。现有父子结构保留不代表仅供 SSH 使用；实施顺序先底座，再 [Authenticator](../archive/2026-10/10-08-authenticator/prd.md) / [SSH 接入](../archive/2026-10/10-08-ssh-terminal-client/prd.md)。初次库 UI/设置/加密迁移归底座，两业务仅接入入口和受限操作。

验收分层（2026-10-10 消除循环）：本 task 先验证公共容器、类型化/审批接口、图事务、会话、管理流程及适用独立平台关卡。上述 AC 中真实 SSH transport 锁库存续、生产配置/信任解析、另一设备恢复后可连接和双方业务导航，保留原目标并在客户端接入后的联合验收补证据，统一追踪于 SSH 父任务及各业务 task；不要求尚不存在的消费者先通过这些场景，才允许开发消费者。公共接口具备接入条件不等于这些联合 AC 已通过，本 task 当前不据此标 completed；消费者实施仍需底座适用独立关卡审阅与既有任务授权，真实设备/账号另按当前授权。

## Out of Scope

HOTP 特化、验证码剪贴板清理/跟踪及其设置/探针、其他平台迁移、云同步及跨 App 秘密 API 均不纳入，不改 Root/HFTP 的既有权限模型。

## Remaining Technical Contracts

全部产品决定按用户最新保留范围整理，HOTP 与验证码清理撤销，当前库只承载 TOTP 与受管 SSH 内容。库实现/资源上限/KDF 参数与平台/native 验证按技术契约推进；技术选择不能扩大范围或弱化既定行为，失败回规划。四 task PRD/design/implement 最新完整规划已于 2026-10-10 获批准，公共底座先行实施。

实施顺序明确为此底座验收 → TOTP / SSH 分别接入；TOTP 页面不是 SSH 的依赖。原生加密文件读取可行性探针宜尽早验证接口，完整客户端集成仍依赖底座验收。当前子任务已启动，配置 B 的当前 APK 安装及隔离验证已获授权；其他目标、真实账号和系统安全配置变更不在授权范围内。
