# Research: ProxyJump signed-NEW pending poll scheduling

- Query: Identify the existing owner-thread, JNI, native relay and mailbox boundaries needed to join the signed-NEW fixture review to the bounded provisional input poll.
- Scope: internal source and the locally pinned OpenSSH 10.6p1 source; no code modification, device, real account, or live network experiment.
- Date: 2026-11-23

## Findings

### Files found

- `android/app/src/main/java/im/majo/ctos/SshNativeSession.java`: exact child/parent owner, signed fixture readiness, Java native-entry guard, relay pump and per-hop deadline.
- `android/app/src/main/java/im/majo/ctos/SshHostKeyReviewMailbox.java`: owner-driven review polling, one-shot UI decisions, cancellation and original time budget.
- `android/app/src/main/java/im/majo/ctos/SshNativeCallbackAdapter.java`: source/candidate/cycle-bound signed fixture review and callback cleanup.
- `android/app/src/main/cpp/ssh_session_jni.c`: process-wide session table mutex and exact callback-token-checked test-only readiness JNI.
- `android/app/src/main/cpp/ssh_native_client.c`: provisional KEX state, guarded parent/relay readiness, bounded child input and failure cleanup.
- `android/ssh/openssh-10.6p1-provisional-input.patch`: restricted non-dispatching OpenSSH packet reader, distinct from the normal packet path.
- `android/app/src/test/cpp/ssh_native_client_test.c`, `android/app/src/test/cpp/ssh_fresh_vault_jni_test.c` and `android/app/src/test/jni-vault-chain/im/majo/ctos/SshFreshVaultRealJniTest.java`: encrypted synthetic peers, relay driver, existing native-only EXT_INFO tests and real host-JNI/vault fixture.

### Code patterns and integration implications

1. **Ticket creation happens outside a prior JNI call.** `signedNewFixtureReview()` checks the exact published child link and original `guardedHopDeadline`, calls `Native.provisionalNewFixtureReady(handle, callbackToken)` after `enterNative`, removes `NATIVE_ENTRY`, then revalidates and claims the review (`SshNativeSession.java:1453–1476`). The state check binds the actual parent, child, callback, view, source, claim, fence and stored hop deadline (`:1480–1502`). `beginJumpInternal` stores that exact deadline only after guarded native jump open (`:2436–2455`). Native readiness rejects other owners, expired roles, revoked views/generations and observed parent closure; it checks signed state and outbound drain, but does not consume child input (`ssh_native_client.c:4385–4437`).

2. **The current mailbox poll is insufficient to convey incomplete input.** `PendingPoll.poll()` returns `void` (`SshHostKeyReviewMailbox.java:11–13`). The signed overload bounds its ticket to the minimum of the role deadline, original review deadline and 30 seconds (`:163–183`, `:8–9`). In `awaitDecision`, a recorded approval is followed by one `poll.poll()` and liveness/time checks, then can return without any readiness result (`:238–283`). The native poll instead returns success plus `idle=0` for a partial child packet or observed parent/relay work (`ssh_native_client.c:4599–4605`, `:4643–4665`). Treating a successful native call as idle can therefore accept a fixture decision while buffered input remains. A correct integration needs an explicit representation of incomplete progress and must keep or reject the decision within the original budget. A loop hidden entirely inside `poll()` must also remain bounded and observe mailbox cancellation; the existing mailbox only checks its own cancellation before and after the callback.

3. **Pumping must occur on the owner after the prior JNI entry returned.** Java `step()` and `pumpJumpRelay()` enter the same thread-local native-entry guard (`SshNativeSession.java:1415–1419`, `:2487–2495`, `:2680–2693`, `:2993–2996`). `Native.step`, `pumpJumpRelay` and the fixture readiness entry take `sessions_lock` and hold it through their native operation (`ssh_session_jni.c:654–663`, `:698–725`, `:729–750`). A native callback inside `step` must not recursively call the parent or child JNI methods: the session mutex is not reentrant and Java deliberately rejects native re-entry. Do separate owner-thread turns outside Java session/callback/vault/mailbox monitors. Existing fixture driving order is `pumpPeers(); parent.step(); child.pumpJumpRelay()` (`SshFreshVaultRealJniTest.java:606–621`, `:849–853`, `:1100–1115`); `pumpPeers` is a test-server action, not a product API. The existing `TerminalChain.step()` additionally calls ordinary `child.step()` (`SshNativeSession.java:1352–1364`), so it is not reusable unchanged for a signed pending child: native explicitly rejects `provisional_new_state == 2` in ordinary step (`ssh_native_client.c:4136–4148`).

4. **One native poll is bounded but its result is an observation.** The poll is owner-only, limits a read to the minimum of 4 KiB, remaining 16 KiB input capacity and the child step budget, decodes at most one supported packet, and checks KEX, service/auth/shell disabled state, role, callback, view, deadline, generation and ancestor liveness (`ssh_native_client.c:4560–4648`). The wire permit is released before `terminal_error` can abort a managed candidate (`:4610–4630`; compare `:1493–1506`); additional generation/liveness checks follow parse (`:4649–4665`). The original guarded deadline is in native `CLOCK_BOOTTIME` milliseconds, and an operation admitted before it may finish after descheduling (`:420–454`). The Java mailbox independently uses its original role/hop deadline plus `System.nanoTime` wall budget and 50 ms wait slices (`SshHostKeyReviewMailbox.java:8–9`, `:109–116`, `:175–180`, `:363–366`). A true idle result is a sequential snapshot, not an atomic permit for subsequent trust write, credentials, UI publication or a guarantee of no future data/EOF.

5. **A normal peer can deliver EXT_INFO before the provisional state starts.** In the fixed upstream `openssh-10.6p1/ssh_api.c:253–290`, `ssh_packet_next` may dispatch KEX/NEWKEYS and then return the next non-dispatched packet within one call. The ordinary client step subsequently invokes upstream `kex_input_ext_info` when the returned packet is EXT_INFO (`ssh_native_client.c:4232–4257`). Only at its later completion check does `completion_digest` set provisional state 2 (`:1432–1467`, `:4331–4334`). Upstream `kex_input_ext_info` increments `ext_info_received` and processes values (`openssh-10.6p1/kex.c:518–555`); the later restricted path rejects a further EXT_INFO if that counter is already nonzero (`ssh_native_client.c:4525–4543`). Thus claims that the restricted path discards without updating auth/KEX state apply to that path only, not every packet that may have arrived during the preceding KEX. This order is source-derived, not an observed race in this investigation.

6. **Relay movement and EOF require active parent progress.** `ctos_ssh_native_jump_relay_pump` moves bounded bytes in both directions, observes parent channel EOF/close, and performs socket half-close only after buffered inbound data drains (`ssh_native_client.c:3548–3618`). `auth_effect_upstream_open` rejects already observed parent/relay EOF, close or shutdown (`:1512–1535`). A FIN or channel EOF not yet read by the parent cannot be inferred from an earlier child readiness sample. The parent must get a bounded step, the exact relay must be pumped, then the child input poll must be sampled again. Preserve the existing short permit and avoid inferring that a later peer event cannot race a completed sample.

7. **The existing native and Java fixtures provide different evidence.** The native-only EXT_INFO modes suppress the server's automatic extension during handshake (`ssh_native_client_test.c:2276–2278`, `:6520–6529`), reach provisional KEX and then send a valid extension via the real synthetic SSH server and parent channel; fragmentation is asserted to produce `idle=0` before the remainder (`:6273–6293`, `:6305–6315`, `:6354–6416`). The Java host fixture drives real Java/JNI and an encrypted synthetic vault, but its current signed-review callback only pumps parent/relay and its poll has no native child input operation (`SshFreshVaultRealJniTest.java:1100–1118`). `pumpPeers()` executes real synthetic SSH peer steps and bridges bytes (`ssh_fresh_vault_jni_test.c:364–377`). A new joined test should positively establish that the extension was delivered after signed pending and consumed by the new JNI/native path, rather than merely finding that a normal automatic handshake succeeds.

### Minimal fixture-only validation matrix

- Exact child/owner/callback: wrong owner thread or other callback/handle must not consume the valid owner's ticket or poison its live connection; missing test-only JNI symbol fails closed. Confirm production release does not export the fixture entry.
- Actual progress: after signed state, feed a legitimate advertised EXT_INFO through the synthetic parent channel, verify parent/relay/child progress and a non-authorizing approval with no auth request, credential callback, shell or trust commit. Test a fragmented extension and an immediately approved ticket: `idle=0` must not produce success before the fragment is completed, cancelled or timed out. Verify the intended new native poll actually ran.
- Liveness: exercise cancellation/close and source, view, role or generation revocation before, during and after an owner poll; inject or arrange observed parent/child EOF and ensure no later approval. Keep exact child/relay/parent cleanup owners when abort or close is unconfirmed.
- Budget: have a non-progressing peer or partial packet reach the original hop deadline, including an immediate UI decision, and verify no deadline extension or busy unbounded callback. A separate test checks timeout/cancel while parent work remains.
- Preserve previous normal direct/known-host and jump regressions, plus native-only one-packet and cipher cases. Results should distinguish synthetic host JNI from Android ART and real sshd, and Java review approval from future trust CAS admission.

## Caveats / Not Found

- No new tests were executed in this research. Existing tests and source provide layer-specific evidence only; none proves the proposed joined scheduler is already implemented.
- This research does not assert that the normal EXT_INFO-before-pending ordering has been dynamically reproduced. A fresh default synthetic server can emit it during handshake, whereas the native restricted-path tests deliberately suppress that emission and arrange a later valid extension.
- Existing packet-poll evidence does not dynamically cover all malformed/authentication-tag/size/compression or extension-advertisement negatives; it cannot be inferred from these scheduling checks.
- Parent/child liveness, Java decision receipt and the native idle output are point-in-time checks. Atomic trust CAS against cancellation, a durable receipt, fresh configuration after cleanup, Android device behavior and actual product first trust remain separate work.
