# Research: SSH 主机密钥变化后的界面路径

- Query: 配置主机私钥连接遭遇主机密钥变化时，用户从终端入口到实际连接要经过哪些
  界面操作；哪些动作可以合并；能否在连接目标区域直接选择配置主机。
- Scope: internal，限 Flutter 入口、界面、状态与相关测试；不研究 native 安全实现，
  不访问设备或用户配置／私钥。
- Date: 2026-11-13

## Files Found

- `lib/main.dart` — 终端导航、会话选择器和 SSH 入口。
- `lib/ssh/password_connect_page.dart` — 受保护连接页、资料选择、冲突处理和首次信任。
- `lib/ssh/library_page.dart` — 受保护 SSH 资料页、配置主机与认证／密钥选择。
- `lib/ssh/host_trust_page.dart` — 冲突告知、旧记录按来源分组、预览、确认与结果回执。
- `test/ssh_password_connect_test.dart`、`test/ssh_host_trust_test.dart`、
  `test/ssh_key_config_test.dart` — 现有交互、选择及失效语义的 widget 回归。
- `.trellis/spec/frontend/terminal-interaction.md` — 现有表单层级、信任和认证的 UI 合同。
- `design/ssh-config-identity-selection.md` — 连接主机时显式选择实际私钥的既有合同。

## Findings

### 现有普通路径与动作数量

1. 导航选择“终端”，终端选择器点击“SSH 连接”（`lib/main.dart:822–840`,
   `:1767–1777`, `:1852–1869`）。入口可能请求通知权限；秘密库锁定时还需要解锁，
   这两种条件性动作不计入下面的基础动作（`lib/main.dart:416–455`；
   `lib/ssh/password_connect_page.dart:65–101`）。
2. 当前配置主机入口在连接页**主连接按钮之后**的“连接资料与密码管理”折叠区：
   展开后点击“私钥与配置”（`password_connect_page.dart:1851–1887,1963–2014`），
   在资料页点配置 Host，随后明确选密码、交互式或某把已导入私钥（`library_page.dart:916–956,1001–1035,1283–1329`）。
   选择成功关闭资料页并将 host/key 放回表单（`library_page.dart:1058–1064`；
   `password_connect_page.dart:525–543`）。如本次服务器要求续接，可勾选对应选项，
   最后点击“连接”（`password_connect_page.dart:1830–1842,2003–2013`）。
   从“SSH 连接”开始，这个示例为 6 次操作：SSH、展开、资料页、Host、私钥、连接；
   续接勾选再加 1 次，不含解锁、权限或输入。
3. 当前 CHANGED 会先结束原请求并显示“服务器主机密钥已变化”，只能点查看旧指纹、
   忘记原有指纹或取消（`password_connect_page.dart:903–945,1177–1195`；
   `host_trust_page.dart:31–64`）。用户点“忘记原有指纹”后：配置主机因来源不确定，
   展开两组记录，用户须为某组点“审阅并忘记”（`password_connect_page.dart:978–995`；
   `host_trust_page.dart:806–879`）；然后确认“忘记旧指纹”（`host_trust_page.dart:540–579,595–614`）；
   操作成功还要点“知道了”（`:664–673,711–747`）；回到表单再点“连接”，首次信任
   弹窗再次点“信任并保存”（`password_connect_page.dart:1020,1336–1372,2182–2202`）。
   因此 config 普通换键恢复阶段本身是 **6 次**：忘记、选择组审阅、确认忘记、知道了、
   再连接、信任并保存。此为从代码静态计数；不同认证、自动来源选择、锁库或服务器
   问题会改变总数。KBI 问题的回答与提交是认证动作，应单独计算，不能当作无用确认。
4. 直接密码／独立交互或直接私钥可从既知组自动开始旧记录预览，因此可能省去第 3 项
   中的分组选择；配置入口不能根据认证类型推测其文件（`password_connect_page.dart:978–995`；
   `host_trust_page.dart:465–516`）。图片中两组指纹相同只是两个来源的显示结果，
   不代表可合并成一个写入对象。截图中第二组在可滚动弹窗下方，长指纹／多条记录还会
   推远可操作按钮（`host_trust_page.dart:819–879,1078–1093`）。

### 可收敛的用户体验（建议，尚非实现事实）

- 在实际当前连接的证据和可操作信任来源均已确定的普通场景，一张界面显示实际主机／
  端口、旧指纹、**本次服务器提供**的新指纹及作用范围；“取消”与“信任新指纹并继续”
  为主要操作。提供展开的技术详情以呈现文件、算法、旧记录数量／其他明细，避免先让
  用户读无关组。长指纹仍应完整、可选择、可换行；不能把尚未完成的认证描述为已验证。
- 一次真实确认只表达对所示新指纹和实际受影响来源的同一连接决定。普通成功过程中
  使用“正在验证并连接”等状态，避免将忘记、成功回执、新指纹确认和再按连接分别做成
  四次决定；只有完成实际连接才显示终端。服务器 KBI 提问仍须用户回答。**新指纹事件、
  生效范围、同次连接能否继续和安全边界均需后端方案支持；现有单纯 CHANGED 弹窗没有
  新指纹，不能仅移除按钮即宣称已实现。**
- 对来源不明、多个真实来源、共享／通配、撤销／CA 等受保护记录、源已改变或写入结果
  不确定，展示准确原因并阻止错误的批量替换或假成功；必要时转入明确的详情／管理
  路径。是否可统一处理以宿主真实结果为准，不能以两条指纹字符串相等代替来源证明。
- 原实现的取消／后台／锁库／超时／路由覆盖／伪造 `pop(true)` 防护以及操作未确认
  回执不能简单删掉。`host_trust_page.dart:549–655,719–759` 和
  `test/ssh_host_trust_test.dart:216–257,294–335,417–462` 体现实际按钮授权、同帧覆盖
  失效及成功／不确定回执；合并普通流程时需设计等价的确切决定、终态和保护生命周期。
  显式用户选择的新交互会改变此前“忘记成功还要知道了＋手动重连”的产品合同；需同步
  更新相关规格和回归，而不是把旧测试一概删除。

### 主连接页直接选择配置主机

**事实。** 连接目标区域仅在已选配置后显示 `InputDecorator('配置主机')` 和“切换到手动
连接”（`password_connect_page.dart:1963–1984`）；唯一非 keys-only 的资料入口在折叠
管理区（`:1851–1887`）。私钥认证下“选择或导入私钥／更换私钥”使用
`_manageIdentities(keysOnly: true)`，隐藏配置主机列表（`:1692–1700`；
`library_page.dart:25–38,1283`）。配置主机列表及认证选择已经复用 `SshLibrarySelection`
类型，并保留密码、独立 KBI 与显式私钥选择（`library_page.dart:12–32,916–1035`）。

**建议。** 在“连接目标”附近增加“选择配置主机”作为连接目标选择，而保留现有次级
管理区、表单顺序和手动目标字段；这在语义上与现有“目标→认证→本次选项→连接→管理”
布局一致（`terminal-interaction.md:117–123`），但具体外观仍需实施后用户验收。最小
复用 `_manageIdentities()` 会将“展开管理→私钥与配置”两次点击变为一次入口点击，
**仍会进入包含导入／私钥卡片的完整资料页**，也可能需要滚动至 Host；不能称为一步
直接显示 Host 列表。若目标是直接列出 Host，可为现有受保护资料流程增加只选 Host 的
模式，或提取复用 Host 列表和 `_selectHost` 的受保护选择器；不能因此自动取唯一密钥，
必须保留每次选认证／实际 key 的明确步骤（`terminal-interaction.md:64–70`；
`test/ssh_key_config_test.dart:531–554`）。已选 config 后也应允许明确更换或回到手动，
不静默覆写原目标。

**返回状态重要现状。** `_manageIdentities` 调用前保存文本目标和 `previousConfig`，清除
密码／口令并打开受保护资料页；返回后无论是否选择，都调用
`_loadDefaults(applyReconnect: false)`（`password_connect_page.dart:457–495`）。后者会
重置身份模式、身份、config、续接选项及秘密（`:255–280`）；只有 `keysOnly && selection
!= null && previousConfig != null` 才重新查库校验并恢复 config（`:497–523`）。取消后
仅恢复 host/port/username 文本（`:525–545`），不能假设旧 config 绑定或认证模式仍在。
这是静态调用链判断，尚未运行该取消场景；新增主入口前应加有意义的回归，明确取消时
公开选择如何恢复及是否需重新验证。即便恢复公开选择，也不保留／回填已清除的密码或
私钥口令；资料期间若目标、key、绑定、库状态或生命周期变化，提示重新选择并停止。

### 交互验收建议

1. 同一已知、允许替换的来源与目标：测试点击连接后只出现一张实际新旧指纹确认；一次
   明确点击“信任并继续”后，不要求再次忘记、确认、应答成功回执或点击连接；最终进入
   的是原用户选择的目标／认证，KBI 问题出现时仍由用户回答。
2. 取消或拒绝、弹窗覆盖、后台／锁库、超时、目标／来源／key 变化、重复或伪造决定、
   迟到成功及不确定写入：无越界信任或误报连接；真实终态按生命周期留存并呈现。
3. 同一指纹存于两个来源时，只操作真实授权来源；受保护／共享记录不可通过简单替换
   跳过。保留首次主机、非换键错误和已有手动信任管理路径。
4. 连接目标区的主机快捷入口：从空配置、无密钥、单密钥、多密钥、密钥删除／配置变化、
   选择取消、后台、窄屏／大字／键盘各验证真实状态；单 key 依然是显式选择，取消不
   启动连接或错误变为手动／密码；登录秘密不因返回被保存或回填。

## Caveats / Not Found

- 本研究未操作真实设备、未读取用户配置或私钥、未运行测试；点击次数按代码静态推导，
  设备权限、锁库、输入法、滚动和认证方式可能增加或减少动作。
- 新指纹证据、准确实际 trust source、CAS／写入、KEX 和同一 owner 是否可安全继续，
  由另一项后端研究负责；不能仅凭本文件实施信任写入或自动重连。
- 对资料选择取消后的模式重置为源码推断，未有专门的合成 UI 测试证明；建议实施前后
  独立复现并保留实测证据。
