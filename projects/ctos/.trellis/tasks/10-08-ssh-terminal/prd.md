## Goal

在 ctOS 的“终端”中增加 APK 内 SSH 与 config 主机一键连接，参考已有 App Shell、Root PTY；先交付 App 统一主口令秘密库及设备快捷解锁等配套，再由 SSH 接入受管文件/身份/凭据能力，与 TOTP 共用基座。

## Background

已核实的当前行为：

- 终端只有“应用 Shell”和“Root PTY”，共用 xterm、底部输入、五个快捷键及输出选择页。入口在 `lib/main.dart:1671`，输入组件在 `lib/terminal_interaction.dart:9`。
- JNI 的启动参数固定为 `/system/bin/sh -i` 或 `su -p`，不能直接启动任意客户端：`android/app/src/main/cpp/pty.c:18`。
- APK 内置 Python 3.13、cryptography 等依赖，当前 Dart/Gradle 依赖没有 SSH 客户端：`pubspec.yaml:8`、`android/app/build.gradle:35`。
- Portable 工具从 APK 原生库目录执行，配置/资源放 App 私有目录，禁止包覆盖 HOME：`android/app/src/main/java/im/majo/ctos/PortablePackages.java:61`、`:205`。
- 生命周期文档与当前源码存在差异：`MainActivity.java:320` 的 onStop 仅取消工作台 Python，`:330` 的 onDestroy 才调用 stopTerminal。SSH 服务需独立持有会话，不能照搬“已自动回收”的假设或顺带修改旧 PTY 的生存期。

## Requirements

R1–R11 汇总用户已确认的需求与达到这些目标所需的具体交付契约；原生构建、格式支持及平台行为的未实测项单列在 Technical Notes，不以规划替代验证。

- R1 / APK 能力：客户端及必要运行依赖随 APK 提供；无 Root 设备可使用 SSH，不要求 Termux、设备已有 ssh 或运行时下载。
- R2 / 终端体验：在“终端”增加 SSH 入口，参考两个已有终端，支持远端交互 Shell、UTF-8 输出、尺寸调整、Ctrl-C / Tab / Esc / ↑ / ↓、输出搜索和复制。SSH 连接后用户输入及控制键交给远端处理，↑/↓ 不由 ctOS 本地历史截获；远端程序自身定义操作，ctOS 不追加程序专属逻辑或用户切换模式，不设特定远端程序的兼容验收。本机 App/Root 终端不回退。
- R3 / config 与一键连接：config 是连接配置的权威来源；从明确的 Host 别名生成主机列表，显示别名和解析后的目标，点选后发起连接。通配规则参与匹配，不伪造为具体设备。一键连接允许首次主机确认及必要认证交互，不承诺无密码操作。
- R4 / 状态与恢复：区分连接中、待确认、认证中、已连接、失败、主动断开、远端退出；可取消连接或重试，禁止重复连接、跨会话输入和远端输出冒充本机状态事件。
- R5 / 已确认认证与信任：未知主机展示实际地址、端口、算法与 SHA256 指纹；用户接受后保存信任记录，指纹变化阻止正常连接并提供核验恢复。config 不能跳过核验，no/off、自动接受未知指纹等违反该规则的有效选项报错并阻止受影响连接，不静默替换；根文件、Include 及每一跳一致执行。认证秘密不得进入命令历史、输出快照、日志或普通配置文件。
- R6 / 已确认配置兼容方向：首版包含 Include 与 ProxyJump，基础及主要 SSH 连接行为以 OpenSSH 为参照；包括 Host / HostName / User / Port / IdentityFile / IdentitiesOnly / ConnectTimeout / ServerAliveInterval / ServerAliveCountMax，以及 HostKeyAlias / UserKnownHostsFile / RemoteCommand / RequestTTY 等主要连接选项，及注释、引号、关键字大小写不敏感、Host 多别名/通配/否定、首个匹配值优先和 IdentityFile 累加例外。Include 的相对路径、通配、条件引用及多级文件，ProxyJump 的逐跳配置/认证/信任均进入设计和验收。首版支持 config 中的 LocalForward、RemoteForward（固定 TCP 目标）及 DynamicForward（SOCKS4/5），随当前 SSH 会话运行和 Stop，支持重复声明、多条转发及 IPv4/IPv6 地址，遵循 ExitOnForwardFailure 的建立失败语义；默认仅请求 loopback 监听；config 显式要求非 loopback/通配监听（含 GatewayPorts 作用）时，连接前展示监听端、地址/端口、方向及可访问范围并确认。确认绑定当前会话和不可变有效配置，不长期记住对外暴露许可；拒绝取消本次连接，不能静默改地址继续。远端实际监听受服务器决定，无法保证 loopback 时如实说明并纳入暴露确认。包含不执行命令的 Match host/user/originalhost/all；其他条件由固定版本矩阵明确诊断，不静默忽略。配置驱动本地命令按 R9 拒绝，未支持项不可静默改变目标、执行或信任语义。
- R7 / 管理与认证：目录方式 A 已确认，config、Include 文件与用户选择的密钥由用户通过 SAF 主动导入到稳定 App 受管 SSH 逻辑结构，持久副本存入公共加密库，解锁后以受管临时内存/文件访问视图供 native 使用，不持续同步外部目录；沿用 A 方案的内置 config 编辑。支持整目录导入以保留引用结构，单 config 导入缺少依赖时提示用户补充，重新导入由用户主动触发，不能自动删除外部源或静默覆盖既有密钥/信任。常用认证包含密码、keyboard-interactive、RSA/Ed25519/ECDSA 私钥及加密私钥；OpenSSH 格式与适用的 PEM 格式以原生构建逐项验证，无法满足时回规划，不缩减目标。保存方式按 R10；导入先展示对象/冲突，缺失引用补充或取消，替换需用户明确选择，信任记录另行审阅确认。
- R8 / 已确认生命周期：沿用单活动终端与手动 Stop 的心智模型，SSH 与 App/Root 互斥；页面导航、切后台、返回终端及 Activity 重建不主动断开已建立 SSH。用户点击 Stop 或既有“换用”（明确结束当前会话）才主动关闭；后台通知提供返回会话及 Stop。独立前台服务拥有 SSH 资源；远端退出、网络故障或系统终止仍会结束连接，真实状态明确呈现，不自动重连、重放命令或开机恢复。保留连接不延长统一库会话；新连接/新秘密请求检查当前库解锁与用途上下文，已完成认证的明文尽快释放。
- R9 / 已确认执行边界：首版拒绝 Match exec、自定义 ProxyCommand、LocalCommand、KnownHostsCommand 等配置驱动的本地命令执行，显示文件/位置及原因，不提供手动启用开关。保留 Include 与受管 ProxyJump；拒绝自定义代理命令不影响客户端拥有的跳板链。目录导入、主机列表/配置预览、连接以及每一跳均遵守该边界；禁止静默忽略后改为直连。用户主动在远端 Shell 执行命令仍在 R2 范围内。
- R10 / 已确认统一秘密模型中的可选保存：用户主动选择保存登录密码/私钥口令，默认不保存且保留仅当次使用；保存到 App 统一主口令加密库，不另建 SSH-only Keystore 数据库。记录绑定实际目标/账号或私钥身份，配置/密钥替换不静默复用；不写普通 config/日志/输出/历史。连接使用已保存秘密时检查有效公共库会话并建立本次连接的限定操作上下文；锁定时经主口令或已启用的设备系统认证快捷方式解锁，各跳仍独立核验 host key/身份。统一初始化、可关闭快捷解锁、加密导出/来源主口令恢复由公共底座管理；有效前台库会话内不因新连接重复解锁同一库；后台保留时间用户可选，默认 30 秒、0 即锁，锁屏/手动/进程重启锁定，逐次身份/主机核验仍执行。提供忘记单条/SSH 全部凭据，取消/失败不免验证或明文持久化。2026-10-09 用户确认 config/Include/私钥/相关公钥或证书/信任和凭据完整加密保护/迁移；受管副本密文持久化，来源原件不自动删除，导入预览/确认文件引用及信任，失败保留原库。
- R11 / 已确认 App 统一秘密库与公共认证：用户最新明确把 Authenticator 主口令/便携加密库/可选生物快捷解锁/覆盖迁移模型应用到 SSH。公共 AppSecrets 统一 KDF、持久化、设备包装、库会话/代次与迁移；AppAuthentication 统一系统可用性、UI、用途/目标绑定、并发、生命周期、错误及受保护操作。SSH/TOTP 使用同一底座和解锁入口，各自只拥有受限业务 adapter，不返回通用密钥或全局已认证布尔值。主机信任/远端登录/Root/SAF 仍独立，不自动改造无关功能或导出跨 App 接口。此决定替代原设备绑定秘密库和 SSH-only 每次系统验证方案，公共会话/设置/备份/管理口令与隐私配套范围已确定，当前待共同最终审阅。

## Technical Notes

- APK 内真实 native OpenSSH 是主技术路线，Dart/Python 只作比较；版本/哈希/构建依赖/许可证、Bionic/API 28/arm64/16 KiB、私有 home 与路径、认证控制通道、受管 ProxyJump 派生及全链路回收列为实施首个可行性关卡。探针不满足要求时回到规划，禁止自动换路线或删验收。
- 常用认证及主要 config 选项承接“基础、主要功能与 OpenSSH 相似”的初始目标，不推导为提供全部桌面工具。当前交付入口是终端 UI 与 config 主机列表，未增加通用 CLI/桌面依赖；详细选项、导入/并发/资源界限见 [design.md](design.md)。
- 公共认证的 API 28/29 与 30+ 路径、Keystore 认证绑定、失效恢复及 SSH 前台服务/通知/Doze 行为分别验证。后台保留不是系统永不终止的保证；App 私有数据不隔离同 UID 本机脚本或 Root。
- 真实设备、端点、凭据使用须在后续实施范围内获得当前授权；本轮只做文档验证，所有产品 AC 均未运行。
