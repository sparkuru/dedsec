# HFTP SAF implementation evidence — 2026-09-27

Only project-local service/native Python scope; no new permission or dependency.

- [Android shared documents guide](https://developer.android.com/training/data-storage/shared/documents-files): ACTION_OPEN_DOCUMENT_TREE grants the selected subtree; takePersistableUriPermission preserves the actual read/write grant. Android 11+ disallows volume root/Download root and Android/data/obb. A moved/deleted tree can invalidate access. Implementation accepts only the known local `com.android.externalstorage.documents` and `com.android.providers.downloads.documents` authorities, requires a persisted read AND write grant, and reports expired grants. Downloads compatibility is detailed below.
- [DocumentsContract](https://developer.android.com/reference/android/provider/DocumentsContract): createDocument/query child documents/document metadata operate through the provider. `isChildDocument` is public from API 29; API 28 uses API-26 `findDocumentPath`, requiring the returned canonical tree path to begin at the selected root. This is provider-mediated containment, without guessing a raw filesystem path.
- [LocalServerSocket](https://developer.android.com/reference/android/net/LocalServerSocket): named server sockets use the Linux abstract namespace. The service creates a random `ctos-hftp-UUID` name; broker accepts only peers with the current App UID, bounds four workers plus four queued sockets, applies 15-second socket idle timeout, and closes sockets/workers on service stop.
- [AOSP FileSystemProvider](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/master/core/java/com/android/internal/content/FileSystemProvider.java): child checks canonicalize files; createDocument uses buildUniqueFile plus createNewFile/mkdir; renameDocument uses buildUniqueFile then File.renameTo. Rename therefore cannot establish a generic exclusive atomic publish contract under external concurrent modification. The implementation reserves a newly created final document, verifies its exact display name, copies the completed private partial into that owned document, and deletes only request-owned documents on failure. HFTP hides the final document while copying. Other apps may observe the final copy; SAF publication is explicitly non-atomic.
- [AOSP ExternalStorageProvider](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/master/packages/ExternalStorageProvider/src/com/android/externalstorage/ExternalStorageProvider.java): local document IDs and tree operations remain provider-owned. Prefix containment is an additional check, handles the old volume-root `volume:` form, and never substitutes for provider containment.

The path backend rejects all symlinks and special files. SAF lacks a general symlink metadata flag: the restricted local provider and canonical provider containment prevent links escaping the selected tree; file descriptors must be regular files. No claim is made for cloud/third-party providers or adversarial external replacement of provider documents. Android 16 local tree support requires actual device validation; API 28 canonical-path fallback is compiled/lint checked but not device tested in this iteration.

Python optional `password` retains authenticated CLI compatibility. App service supplies no password; default host `0.0.0.0`, port 7888, upload 32 MiB (range 1–1024); private quota is max(128 MiB, 4×upload cap), and downloads retain a separate 1 GiB cap. ToolFiles' normal 32/128 MiB limits are unchanged.


## Downloads shortcut compatibility — device feedback follow-up

The initial device attempt through the system Downloads shortcut was rejected by the ExternalStorage-only allowlist. Its actual authority was not visible in the original error; an explicitly invoked native test can report only its authority (no document URI, path or file names), and requires `hftpExpectedProvider` to verify it. No production diagnostic logging is added. The next isolated device selection must confirm the directory before starting a service.

[AOSP DownloadStorageProvider](https://raw.githubusercontent.com/aosp-mirror/platform_packages_providers_downloadprovider/master/src/com/android/providers/downloads/DownloadStorageProvider.java) is a local FilesystemProvider for Downloads and DownloadManager content. It delegates createDocument to FilesystemProvider's exclusive creation and implements findDocumentPath; isChildDocument inherits canonical containment. Its document IDs may be `raw`, MediaStore IDs or numeric DownloadManager IDs, so the implementation adds only the known local `com.android.providers.downloads.documents` authority and applies mandatory provider containment without interpreting those opaque IDs. The additional volume/path ID-prefix check remains only for ExternalStorage. [AOSP constants](https://raw.githubusercontent.com/aosp-mirror/platform_packages_providers_downloadprovider/master/src/com/android/providers/downloads/Constants.java) defines the Downloads authority. Cloud and arbitrary third-party authorities remain rejected.

The initial picker location uses DocumentsContract.buildDocumentUri for the standard ExternalStorage `primary:Download` document as a display hint only; no URI is translated into a filesystem path or granted without selection. Existing selected trees still supply the initial URI. New native boundary assertions accept both local tree authorities and reject non-tree Downloads URIs/cloud providers. The opt-in `selectedLocalDirectoryProviderIsConfirmed` test verifies the existing selected grant/root metadata and reports only the authority when explicitly passed `hftpExpectedProvider`. No grant or device operation is performed by the implementer.

Main's final TARGET-PHONE check explicitly confirmed Downloads authority, persisted read/write grant and root metadata. Its original ADB-created public fixture was absent from the provider listing (404), while files created through HFTP/SAF uploaded and downloaded correctly. AOSP `queryChildDocuments` delegates raw IDs to filesystem listing but MediaStore directory IDs to MediaStore queries; this supports the inference that the missing ADB fixture is a provider indexing boundary. The app does not translate opaque IDs or scan raw paths to override provider visibility.
