# ctOS 产品与体验改进

## Goal

落实 [改进机会](../../../../../design/opportunities.md) 中的优先建议，让本机观测结果可信、常见操作形成闭环，并使手机界面更易读易用。

## Background

- 探索阶段已完成，证据和建议保存在 `design/opportunities.md`；用户随后要求按建议推进，并授权使用 `adb devices -l` 列出的测试设备验证。
- 2026-09-25 的 `adb devices -l` 只列出 `192.168.9.9:45797`（PLR110）。本轮不能据此声称 Android 11 开发板也在线或已验收。
- 截至 2026-09-28，三个子任务均已完成并归档；父任务现在只负责核对跨任务交付、整理 `design/` 当前状态及修复归档导致的文档链接，不直接修改产品代码。
- 子任务各自的设备授权不延伸到父任务。本轮父任务只复核已保存的验收证据，不安装 APK、不启动应用、不访问设备。

## Requirements

- R1：完成归档的 [可信状态与工作台基础体验](../09-25-trustworthy-state-workbench/prd.md)：快照新鲜度、明确的权限/失败状态、受限字段解释和工作台首屏层级。
- R2：在 R1 的状态模型可用后完成归档的 [只读任务与选择性导出闭环](../09-25-read-only-task-loop/prd.md)：信息对象 → 只读任务 → 结果/历史 → 选择性导出。
- R3：在 R1 的视觉基线稳定后完成归档的 [界面与终端可用性整理](../09-25-interface-terminal-polish/prd.md)：统一展示、连接可读性和手机终端操作。
- R4：维持 App API、Root 采集、App/Root PTY 边界及采样/资源约束；对已移除的 Vector 仅保留历史日期语境；每个子任务独立记录代码、设备与人工验收结果。

## Acceptance Criteria

- [x] 三个子任务自身的验收记录完整；跨任务的信息来源、权限状态、只读任务历史和选择性导出边界一致。
- [x] Flutter/Android 检查、APK 身份和授权设备结论能对应到具体子任务及产物；不把局部设备结果扩大为跨 ROM 结论，也不把历史目标地址写成当前连接状态。
- [x] `design/` 中的架构、规划、变更历史和验证记录与最终交付一致，并区分已实现、已验收及未验证范围。
- [x] 活动父 PRD、归档子任务记录和 `design/` 内相关相对链接在移动归档后均指向实际文件。

逐项证据及未验证边界见 [集成核对](check.md)。勾选代表已有记录可核对；父任务没有重跑产品或设备验收。

## Out of Scope

- 应用/进程/日志的全面对象关联、远程管理、对外服务、动态插件和默认后台任务。
- 未经单独授权的 Root/Vector 配置变更、设备重启、清除数据或卸载其他应用。
