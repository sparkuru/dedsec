## Goal

在 ctOS 内提供离线 TOTP 验证器，与 SSH 共用一个主口令、统一秘密库和设备快捷解锁/设置/备份流程，减少理解与维护成本。领域入口为 [Authenticator](../../../../../design/authenticator.md)，公共契约为 [统一秘密库与认证](../../../../../design/app-authentication.md)。

## Background

恢复时公共秘密库、共同设置/认证及 SHA-1/6 位/30 秒核心发码和条目增删已有实现，API30 锁屏凭证快捷已实测；本轮已补TOTP页面、列表/重命名和扫码，完成本地检查/构建。代码证据/标准/服务兼容见领域入口；标准 TOTP 互操作取决于参数和账号策略，不以 ctOS 品牌审批作普遍承诺，本轮没有服务登录实测。

## Requirements

- AUTH-01：ctOS 自有第三方 TOTP 验证器，作为公共秘密库的受限业务消费者。
- AUTH-02：按 RFC 6238/标准服务 otpauth 入口说明兼容面；专有 MFA/组织策略可拒绝，不承诺所有 MFA 通用。
- AUTH-03：按最新用户批准复用已有规划并实施；任务状态、实现及验证分别记录，不推定设备/账号授权。
- AUTH-04：本地离线 TOTP；相机扫码、手机图片读码、手动添加；多账号代码/倒计时/主动复制/重命名/删除，无云同步。
- AUTH-05：解析并校验 type/issuer/label/secret/algorithm/digits/period；已确定基础参数 SHA-1/6 位/30 秒。不支持的类型或参数组合明确拒绝，不静默生成另一种代码；未确定算法/位数/周期扩展不作为本次必交付范围。
- AUTH-06：秘密不进入通用日志/历史/诊断/工具共享库，锁定清理种子/代码缓存和旧请求。敏感页面保护与主动复制接公共 BASE-13/14；截图/录屏/任务预览不显示秘密，主动复制标敏感。2026-10-10 用户撤销剪贴板清理及其设置/跟踪/探针，验证码清理由用户自理；不宣称彻底擦除托管/系统副本或防住 Root/同 UID。
- AUTH-07：复用 ctOS 完整加密备份，包含 TOTP 种子及已受管 SSH 凭据/config/Include/私钥/关联公钥或证书/主机信任。来源主口令认证解密、内容校验/预览及明确覆盖后原子提交；已有目标另验证当前主口令，空目标只需来源，失败/取消保护旧库。设备材料不迁移，成功后重新登记；服务恢复码由服务签发。
- AUTH-08：首次需要秘密进入公共设置/导入，主口令经 KDF 派生密钥，密文持久化、内存临时解密。共享有效前台会话，锁屏/手动即锁/重启锁定，后台保留可调秒数（默认 30、0 即锁）；不另建验证器主口令或密文格式。
- AUTH-09：首版含公共更换主口令：本次旧口令认证解密、新口令确认、完整库重新加密及原子换代；提交前失败保留旧库，提交后快捷登记失败回新口令。旧备份仍用旧口令，TOTP 种子/SSH 业务秘密不变；管理再次验证/旧备份规则接 BASE-10/11。
- AUTH-10：设备生物/系统锁屏快捷解锁可开启/跳过/关闭；关闭须本次主口令认证解密，错误/取消保留原状态，成功清理设备材料并锁定，库与条目保留（BASE-12）。普通信息/终端不增加 App 登录墙。
- AUTH-11：TotpAdapter 只管理自身条目/算法/展示，公共 AppSecrets/AppAuthentication 拥有 KDF/密文/会话/代次/设备材料/迁移。逐次检查 consumer/操作/条目/库代次，不向 Flutter 返回数据密钥或任意其他秘密。
- AUTH-12：“工作台 → Authenticator”独立入口，验证器/SSH 共用唯一“秘密库设置”；主口令/快捷/后台解锁保留秒数/备份集中管理，无验证码清理设置。首次设置/导入/解锁回原业务、取消无半成品，接公共 BASE-15，不作为普通 Python 工具执行。
- AUTH-13：系统选择器只读取用户所选图片，宿主离线有界解码；相机/图片共用标准 URI 校验和条目确认，多码明确选择，不自动整图加入。短期种子/URI 不进入日志/导航/明文缓存；取消/锁定/换代/迟到不改条目，资源和短期授权回收；未选图不扫描，原图不改/不自动删除，扫码库/必要模型随 APK。
- AUTH-14：范围限定离线 TOTP 与 ctOS 自身加密备份，其他平台专有迁移排除；完整库的 ctOS 跨设备恢复和已确认 SSH 文件/凭据保护保留。

## Acceptance Criteria

以下是产品验收要求；本轮本地证据与仍待设备/账号/混合业务执行的项目分别映射在 [check.md](check.md)，不把实现或mock作为全量验收通过。

- AC-01 → AUTH-01/04/05：支持的 URI/手动组合生成正确代码；RFC 6238 对应向量、窗口边界/前导零/2038 后时间及无效类型/参数有验证，拒绝不支持组合时不默默按默认生成。
- AC-02 → AUTH-04：断网生成；系统时间/前后台改变后代码与倒计时正确，不冻结旧码。
- AC-03 → AUTH-02：真实服务绑定/登录在另获授权后按实际账号策略记录，不支持专有流程有明确原因；未测不标通过。
- AC-04 → AUTH-06/08：初始化取消无半成品，锁定不能读取种子/生成代码；明文库/秘密不落盘、不进入通用输出。BASE-13 页面/路由/对话框/后台/SAF 返回保护、BASE-14 用户主动复制/敏感标记/无清理和跟踪有验证；平台限制与实测分开。
- AC-05 → AUTH-07/09：同一主口令格式的混合 TOTP/SSH 库跨设备恢复；失败/取消/确认前原库不变，成功只采用来源完整库。代码及 SSH 文件/身份/引用/用户批准信任一致，设备材料不迁移，SSH adapter 验证文件与信任。
- AC-06 → AUTH-03：PRD/design/implement、上下文、任务状态和当前授权一致；本地实施与实测分开，未经授权不安装设备或操作真实账号。
- AC-07 → AUTH-07/08/09：错口令/截断/头部或内容篡改/超限/不合规内容拒绝提交，认证前不消费明文；生物成功或前端 trusted 标记不能跳过管理验证。改口令提交前失败保护，新库新口令/旧备份旧口令、内容关联不变、旧代次/包装失效及重登记失败回退正确。
- AC-08 → AUTH-08/10：首次使用可开/跳过快捷，关闭前新输入口令；错口令/取消不改状态，成功保留条目/文件并锁定、回主口令。前台跨业务有效会话不重输，共用后台秒数/到期、0 即锁、锁屏/手动/重启锁定；普通页面不被阻塞。
- AC-09 → AUTH-11：两个业务使用同一秘密设施，consumer/操作/条目/库代次/取消/迟到回调拒绝错用；无验证器或 SSH 专属的第二套 KDF/库/设置。
- AC-10 → AUTH-12：工作台验证器与共同设置可达，TOTP/SSH 设置/库状态一致；原业务返回/取消无半成品，导航不主动断开已建立 SSH，管理操作仍需本次主口令。
- AC-11 → AUTH-04/06/08/13：用户选图、离线识别/参数确认/主动添加与相机/手动结果一致；相机拒绝可用图片/手动。空白/损坏/专有码/多码/超大字节像素候选/超时、URI 失效/取消/锁库/换代/迟到不自动添加或覆盖；外部原图不改、未选图不读、种子无明文缓存、临时资源回收。

## Out of Scope

HOTP 及其计数/发码/校准/恢复全部撤销；验证码剪贴板清理及其设置/跟踪/探针、云同步、Google 批量迁移码/其他平台备份或迁移、专有推送/数字匹配、Passkey/FIDO2、短信/邮件、自动向 SSH/浏览器填码和服务端 MFA 系统均不做。

## Scope and Dependencies

复用 [统一秘密库底座](../../../10-08-app-authentication/prd.md) 已实现且已审阅的公共合同与适用平台证据接入 TOTP；不依赖 [SSH 客户端](../10-08-ssh-terminal-client/prd.md) 完成，两个业务可分别推进。共同初始化/设置/KDF/密文/设备包装/导入导出由底座拥有，本 task 负责 TOTP 业务及集成验收。

## Technical Validation and Artifact Status

产品决定按最新剩余范围整理，验证码清理由用户自理。KDF/密码库、扫码实现/许可证、字节/像素/条目等资源上限及后台保留设置合法范围依技术契约固定；不因此扩大产品范围。真实 Keystore/安全窗口与 SSH 无明文磁盘文件视图需验证，失败回规划。公共底座仍 in_progress，未测平台和混合业务联合验收保持开放；用户已授权本 TOTP 本地实施及后续`.14`安装/独立自动验收，不把底座全量验收作为业务接入的循环依赖。没有真实服务账号授权。
