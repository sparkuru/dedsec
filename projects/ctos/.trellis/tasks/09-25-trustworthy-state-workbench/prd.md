# 可信状态与工作台基础体验

## Goal

用户在工作台和连接页能判断数据是否仍可信、受何种权限限制以及如何恢复；Android 16 的受限负载有易懂说明，首屏能直接进入常用操作。

## Background

- `lib/main.dart:398-400,583-586` 只在连接缓存为空时自动读取；`978-1045` 没有采集时间，空结果文案混合未采集与无匹配。
- `MainActivity.java:135-140` 会返回 `rootError`，Flutter 未显示；`lib/main.dart:359-371,548-562` 将能力压缩为 Root/APP 和 Vector 布尔状态。
- `DeviceSnapshot.java:38-47` 读取 `/proc/loadavg`；`design/verification.md:21` 记录 Android 16 上被 SELinux 拒绝；`device_page.dart:85-90` 直接呈现异常文本。
- 2026-09-25 只读 `adb devices -l` 列出 `192.168.9.9:45797`（PLR110），未列出 Android 11 开发板。用户已允许使用列表内设备验证。

## Requirements

- R1：连接页分别表现未采集、采集中、当前结果、部分结果、旧结果、刷新失败和真实无匹配；保留最后成功数据时必须显示时间及旧数据标识。
- R2：工作台将 App 基础能力、Root 采集会话和 Vector 桥接分开表达，明确来源及手动恢复动作；不得因轮询重新申请 `su`，不得把 Vector 无回应断言为未安装。
- R3：系统负载需明确区别于 CPU 使用率。读取受限时展示简短说明和仍可用的信息；原始错误可按需查看，不以 0 代替未知。
- R4：工作台首屏按“设备摘要 → 需要注意的状态 → 常用入口”排序，保持现有深色/薄荷色身份；窄屏、大字号和大屏均可操作。
- R5：保留网络速率、Root 会话、Vector 桥接、PTY、导出和前后台采样的现有行为；实现后同步 `design/` 的架构、变更与验证记录。
- R6（用户追加）：在“信息 → 连接”增加解析层，将现有 `ss -tunape` 原生文本变成逐条连接 item；保留原始输出与无法解析的诊断行，筛选继续支持地址、端口、UID、包名。
- R7（用户追加）：可归属应用的连接 item 展示应用图标与名称；检索覆盖应用显示名、应用自身名称、进程名和包名。同 UID 多包不得假定唯一归属；图标不可取得时仍保留可检索身份。
- R8（用户反馈）：打开 QQ 等应用后返回 ctOS 或重新进入连接页应更新快照，使名称检索反映新连接；支持应用分身的独立 UID 及可得的自定义别名，例如 Oplus QQ 分身 `tim`。别名不可得时标明原名、包名和用户 ID，完整名称匹配优先于宽泛子串。

## Acceptance Criteria

- [ ] 模拟连接首次进入、权限受限、无匹配、成功后刷新失败及前后台切换，页面状态/时间与实际快照一致。
- [ ] Root 失败或会话终止时有明确恢复入口；无自动重复授权；Vector 未响应时保留可用的 App 数据。
- [ ] Android 16 受限负载显示人可读说明和原始详情；可用负载明确标为系统负载。
- [ ] 360dp 级窄屏、较大文字及平板宽度的工作台无溢出，主要状态和常用入口可见。
- [ ] Flutter 分析、测试、相关 Android 检查及用户授权手机的定向回归记录实际结果；Android 11 未在线时明确列为待验收。
- [ ] 连接列表逐条显示协议、状态、本地/远端、可得的 UID/应用信息；异常输出不伪装成空连接，仍可查看原文。
- [ ] 已知应用的连接 item 显示真实应用图标、显示名与包名；同 UID 多包可展开查看，显示名、应用自身名称、进程名和包名均能筛选。
- [ ] 新打开 QQ 后返回连接页可找到新快照；分身 UID 与主应用分开显示，可按 `tim` 别名、QQ 原名或包名检索，非 Oplus 设备别名缺失时仍可识别用户及包名。

## Out of Scope

- 不改 Root/Vector 授权配置、不重启或清除设备数据；不为 CPU 负载引入未经实测的新采集源。
- 命令历史、选择性导出和终端快捷栏由兄弟任务实现。
