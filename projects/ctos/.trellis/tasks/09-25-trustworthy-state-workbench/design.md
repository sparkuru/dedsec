# 技术设计：可信状态与工作台基础体验

## 边界与数据流

保留 `MethodChannel('ctos/native')` 与 Java 返回格式。`snapshot` 的 `kernel`、`root`、`moduleActive`、可选 `rootError` 和 `connections` 的 `output`、`partial` 不更名；Flutter 在 UI 层建立有类型的采集状态。连接状态记录最后成功快照、采集时间、加载/错误状态；刷新失败保留数据但标为旧数据。重进连接页时不自动丢弃旧数据，应显示时间并允许手动刷新。前后台恢复时按现有采样规则处理。

Root 状态从当前快照及 `rootAuto`/手动授权结果推导，不把 App 与 Root 当互斥能力。Root 会话终止原因优先使用已有 `rootError`；Vector 只根据实际响应标“在线/未响应”，不推断用户的 Vector 配置。自动授权仍限启动一次，失败后只能手动重试；不修改 Java Root 会话策略。

设备负载仍来自 App 权限的 `/proc/loadavg`。页面标题改为“系统负载”，加一句“不是 CPU 使用率”；`permission_denied` 等状态显示简短原因与可展开原始异常。内存/电源等可用分区继续展示。

用户追加的连接 wrapper 留在 Flutter 层，不变更 `Collector.connections` 的 JSON 合同或 Root 命令。`ConnectionReport.parse` 读取 `ss -tunape` 行，识别协议、状态、队列、本地/远端、UID 及 Java 追加的 `↳` 应用归属；标题与权限/格式诊断单独保留。列表按 item 字段筛选，原始输出可展开。对无法解析且非空的输出显示采集提示，不把它说成零连接；大列表延迟构建 item。

用户再次追加应用图标与多名称检索后，`Collector.connections` 在原有字段上增加可选 `apps` 映射：键为本次输出中的 UID，值为该 UID 可得应用的显示名、包名、`ApplicationInfo.name`、进程名与小尺寸 PNG 图标（Base64）。只对本次出现的 UID 取图标；对包可见性受限或无法编码图标的应用保留包名，UI 显示通用占位图标。Flutter 在采集完成时解码并缓存，同 UID 多包以一个主项加可展开的其他包展示，不宣称每条 socket 唯一归属某包。原有 `output`、`partial` 合同不变。

用户反馈 QQ 搜不到及分身别名后，连接页在重新进入和从后台返回时刷新快照，保留加载中的旧结果及失败回退。Root 连接命令在 `ss` 后增加固定只读的多用户包列表、用户序列号及 Oplus 桌面收藏项查询；仍保留原有 `output`、`partial`，只向 `apps` 增补 `alias`、`userId`。包列表的一个包可能携带多个 UID，按完整 UID 映射；别名不可得时回退到原名、包名和用户 ID。Flutter 搜索完整应用名/别名/包名时优先精确匹配，然后才使用通用子串匹配。上述 OEM 别名来源仅在 PLR110 实测，不把它写成跨 ROM 保证。

## 视觉与交互决策

基于本项目 UUPM 检索与现有截图，沿用暗底、薄荷色主动作和 Material 控件，不引入第二套主题或新图标依赖。工作台把可操作的异常/受限状态放在设备摘要后，网络和信息入口放在同一首屏路径。状态由文字与图标共同表达，颜色只作辅助。用 `LayoutBuilder` 或等效约束为大屏限制内容宽度，手机单列；触控目标按 Android 约 48dp，正文与辅助文字保持可读。相关依据见 `research/ui-and-state.md`。

## 兼容性与取舍

- 不改变 native JSON 合同，减少对既有设备测试的影响。若为了错误分类必须补字段，需先同步合同、测试和架构文档。
- 对未知/过期值保留 `—` 或状态说明，绝不默认为零。
- 连接的“旧”由最后成功时间和最近失败/切页情况决定；具体阈值写为常量并测试，不让一个全局更新时间掩盖各数据源差异。
- Android 16 当前在线手机可验收；Android 11 开发板未列出，当前切片记录为待验收，不以历史结果替代。

## 回退与风险

主要风险是新增状态模型与 `IndexedStack` 页面缓存相互作用、Root 错误短暂消失、工作台字体放大溢出。分步提交状态模型与 UI，再用频道桩、组件测试和实机检查；如需回退，保留原生调用与现有数据格式即可撤销 Flutter 层改动。
