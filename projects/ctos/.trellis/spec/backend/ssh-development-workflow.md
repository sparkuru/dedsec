# SSH 开发：倾向优先实现，禁止过度测试

本规范适用于 SSH 父任务及其后续 SSH 相关实现、审查和协作。用户当前指令优先于本规范和其他规范中的默认测试建议。

## 倾向优先实现

- 需求和边界明确时，先推进实际功能或修复，优先完成可供使用或审阅的端到端实现；不要把搭建测试夹具、反复设计测试矩阵或扩大测试范围当成默认前置步骤。
- 选择足够小而完整的实现切片，复用现有代码和机制，并如实保留尚未实现或尚未验证的边界。不要为了等待更多测试而搁置可独立完成的实现。
- 除非用户要求或已有明确必要性，不为了测试而新增大规模框架、重复夹具或与实现一一对应的测试。

## 禁止过度测试

- 禁止无明确必要的重复运行、堆叠相同覆盖、多轮全量测试、穷举组合或超出当前改动范围的测试。一次适当检查已有结论后，只有实现变化、新故障或具体未解决问题能够解释额外检查的必要性时，才扩大或重跑。
- 选择与变化直接相关、能够区分实际行为的最小必要检查；按当前用户安排将测试交给执行方，不要把增加测试数量当成进度，也不以历史测试通过推断当前版本已验证。
- 如实报告实际执行过的检查和未验证部分，不为了减少测试而将未运行的检查标为通过，也不通过降低断言或移除既有保障掩盖失败。

## 当前用户指令

2026-11-27 用户先前要求“验证”后已执行的检查作为历史证据保留；最新安排由其他 agent／session 执行产品测试，主 Codex 编排测试单、独立审核结果并管理项目状态。测试单和协议见 [Agent 间测试交接](../../../design/agent-test-handoff.md)，Codex 的具体分发与审核流程见 [测试管理说明](../../../design/codex-test-management.md)；校验 JSON、路径和文档不属于产品测试。用户明确另行指定时按新指令执行；开发板安装、真实账号与其他设备操作仍须当前任务的明确授权。
