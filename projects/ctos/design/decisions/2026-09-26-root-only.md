# 移除 Vector，使用 App API 与 Root

日期：2026-09-26。来源：用户要求不保留现有功能用不到的 Vector 依赖。

## 背景与现场证据

PLR110 / Android 16 当前连接为 192.168.9.9:44603，Root id 返回 uid=0，uptime 3517107 秒（约 40.7 天）。Vector v2.2 (3094-8a156495) 的现存日志记录 ctOS 模块在应用 PID/UID 10497 中加载，未见 ctOS 的 system_server 入口/bridge ready 记录；dumpsys activity broadcasts 只有 App 的 RESULT 接收器，没有系统 QUERY 接收器。

旧 SystemModule 仅对 android / android 的 loadPackage 执行，且需 AMS.systemReady 后注册查询入口。因此模块在 ctOS App 内加载不会提供系统桥接，勾选作用域也不代表运行中的 system_server 已注册服务。启用发生在系统启动之后且尚未重启，与现场证据相容，但本轮未读取作用域数据库或重启，不能断言这是唯一原因；也未验收 Vector 在该 ROM 的重启加载兼容性。

## 决定

移除 SystemModule、Xposed API jar、xposed_init、Manifest 元数据/查询权限及 App 广播客户端。移除 moduleActive/module/moduleAgeMs 快照字段，Flutter 与导出使用 App 网络配置和 Root 接口快照。ctOS 不再要求 Vector 作用域或系统重启。

Root 采集原本已覆盖接口流量/错误/丢包、全部路由表、TCP/UDP 与 UID/应用/分身映射，PTY 也独立通过 su 工作。设备、电源、内存与 App 可见网络由普通 API 获取。无需为了使用这些能力在 system_server 注入代码。

## 影响与边界

- 需要增强采集时由 Root 管理器授权 ctOS，失败后保留 App 基础信息和手动重试。
- 未授权 Root 时不再有 Vector 作为额外接口数据源。网络配置是 App 可见范围，不承诺与 UID 1000 相同的跨用户/VPN 可见范围；Root 接口与路由仍可观察内核数据。
- 应用不改 Vector 或其他模块配置，不卸载设备上的 Vector。现存管理器记录由设备管理器自行更新；其他应用仍可继续使用 Vector。
- 历史 Vector 验收记录保留为历史，不再作为当前产品验收条件。回退包在 /tmp/ctos-before-root-only-20260926.apk，临时证据不承诺长期保存。
