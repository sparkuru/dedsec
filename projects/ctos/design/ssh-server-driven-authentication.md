## 用户期望

连接页首先加载已有配置或输入用户名、主机、端口，私钥由用户按需明确选择；不要求
预先判断密码与服务器问题属于哪种 SSH 认证。连接后先核对实际主机指纹，再依实际
服务器答复进入认证：需要密码时询问，需要回答问题时展示服务器真正的问题；如果只
允许公钥而没有提供可用私钥，或者提交的凭据被拒绝，应清楚告知并结束或允许用户重新
连接。私钥不会因配置文件路径或历史记录被静默选中。

服务器可能只逐步透露下一步，并不保证一次列出完整的多因素结构。界面应按实际答复
逐步前进，不猜测后续问题或向用户宣称已知服务器完整认证流程。

## 设计边界

- 同一连接先完成真实 KEX、主机键核验及必要的未知／变化指纹确认，再开始发现和认证。
  保持原目标、配置来源、受管私钥、owner、KEX、会话和原始期限绑定；取消、后台、
  锁屏、视图或配置失效仍结束本次连接。
- 在受信会话中按 SSH 协议请求初始可用方法；方法列表只是当前服务器答复，不证明任意
  方法必然成功。服务端可能直接返回不需要额外凭据的认证成功；须把它作为真实
  无凭据认证处理，不冒充已经验证过密码或私钥，也不再发送其他认证请求。
- 同时考虑服务器实际列表、配置中的认证开关与 `PreferredAuthentications` 顺序、
  本次是否明确选了私钥。默认优先顺序参考项目固定 OpenSSH，实际不可用或不受支持的
  方法不能静默当成已实现。只支持公钥但无可用私钥时提示选择私钥；所选私钥被拒绝时
  明确失败，不猜其他密钥。
- 密码和加密私钥口令只在确实需要时，通过原连接受保护、一次性且可取消的提示收集。
  自动提示默认仅本次，可显式保存新输入或使用精确匹配的已存项。服务器交互问题继续
  展示实际名称、说明、prompt 和 echo 标志，只使用每轮用户提供的回答。
- 服务器返回的普通拒绝不是成功或部分成功：如果服务器仍列出其他可用方法，按配置
  次序询问尚未尝试的方式；只有公钥且所选密钥被拒绝时明确失败。不得重放被拒绝的
  凭据或猜测另一密钥。真实 PARTIAL 表示尚需下一因素，两种情况均只考虑服务器随后
  的实际列表，并继续遵守配置政策和原期限；每次提示和响应绑定本连接、本阶段及原
  保护上下文。过期、取消或旧结果不能恢复会话。
- 只有服务器真实认证成功、会话 shell 成功、原认证材料退休后才交付终端。先实现并
  验证新路径，再替换原连接页的显式认证模式；过渡期间保留独立 KBI 首方法和旧调用，
  避免现有服务器失去入口。此前 `RequestTTY no`、服务器保活和主机信任修复继续保留。

## 当前实现与工程切分

1. CSCP／CSPP v5 传递固定 OpenSSH 实际配置的受支持方法次序；自动连接计划 CSASv4
   冻结目标、允许方法及可选明确私钥，不包含登录密码。旧版本和显式连接仍受原合同约束。
2. 实际 host／KEX／userauth 完成后发送一次 `none`；根据当前方法列表和配置顺序选择，
   `none` 成功是独立结果。每个方法最多尝试一次；真实 PARTIAL 才允许读取服务端下一
   列表，并在原连接中继续。某一方法普通拒绝后可转到服务器最新列表中的其他允许
   方法；明确拒绝不自动重放凭据或猜测另一私钥。
3. 密码及加密私钥口令通过原角色、会话阶段、host／KEX、期限和前台状态绑定的一次性
   票据请求；服务器 KBI 问题沿用实际 challenge，不与本地密码提示混同。取消、锁屏、
   超时和迟到回复不能复活连接，拥有的字节副本在各层清理。等待本地输入时使用专门
   的有界连接检查处理真实 banner／断线并拒绝未请求的认证结果；不能调用在空闲或
   PARTIAL 状态返回 EALREADY 的普通会话 step。
4. 默认表单输入目标并可选私钥，原显式密码／私钥／独立 KBI 位于“其他认证方式”。
   用户选择的 config 禁用公钥时仍可使用密码、KBI 或服务端真实 `none` 成功；其可选
   私钥列表为空。自动重连仅携带公开目标和可选 key id，不携带旧输入或授权。
5. 自动提示的已存项由公共加密库按实际主机、端口和用户名或所选加密私钥的确切身份匹配。界面接收可用性，用户勾选后只提交复用意图。连接 owner 在同一请求和主机证明下读取凭据。新输入只有在用户显式勾选、对应因素被服务器接受、最终认证和 shell 均成功后才在发布终端前保存。两个因素都符合时逐条执行已有的受保护写入并核对回执。所有输入和待保存副本在消费或结束时清理。

验证记录分别报告配置和加密合成 peer、Java 会话与票据、Flutter 界面，以及用户在指定板上的逻辑验收。自动保存和复用已完成指定板的[隔离密码界面和私钥桥接验证](verification.md#20261118-ssh-automatic-credentials-device)。[隔离 OpenSSH](verification.md#20261118-ssh-openssh-interop) 已验证 ARM64 原生 KBI 首方法及密码后 KBI，[指定板端到端](verification.md#20261118-ssh-openssh-android-ui)随后验证了同两条手动目标路径；其他服务器和公钥后 KBI 不由此推定。

## 独立交互认证入口

2026-11-18 决定暂时保留“其他认证方式”中的独立 KBI。默认手动目标无私钥时会优先使用服务器提供的 KBI，本轮设备验证了 KBI-only 和密码后 KBI；但 config 自动入口按配置的 `PreferredAuthentications` 顺序选择。例如配置为 `password,keyboard-interactive`，且服务器同时提供两种可选方法时，自动入口先提示密码，该提示目前没有跳过方法的动作。独立 config KBI 在配置允许 KBI 时可直接选择服务器问题，而不必先输入或拒绝密码。这是当前源码中的实际行为差异，不由本轮测试推定所有服务器都需要该入口。若未来要移除入口，需先明确接受这一行为变化或提供受配置和服务器答复约束的替代选择，并分别验证 config 路径。

## 验证要求

分别覆盖 `none` 成功／仅密码／仅 KBI／仅公钥（有、无、错误私钥）／多方法及真实
PARTIAL、配置禁用与顺序、重复和畸形服务器答复；验证提示出现在指纹确认之后、
同一连接的手动回答、保存选项、取消／锁屏／超时／迟到结果和无凭据泄漏。合成加密
peer、配置与 JVM、Flutter 窄屏／横屏／大字、Android JNI/设备和真实服务器分开报告。
本任务范围内不自动连接真实账号，不把旧设备或安装授权当成本次授权。
