# SSH 终端：请求确认前收到通道输出

状态：2026-11-16，接续服务器保活设备验证时发现；源码修正、加密合成协议回归及
候选构建通过，用户授权安装后在指定板的同一提前输出时序复测通过。

## 问题与依据

session 通道已打开后，服务器可能在 PTY 或 shell 请求的成功答复之前发送通道数据。
真实设备上，受限合成服务按“shell 数据先于成功答复”的顺序发送后，旧候选断开；
同顺序的 ARM64 加密协议夹具可复现旧代码的协议错误。结合这两条证据，判断旧客户端
假设请求答复必先于通道数据，是此次设备失败的原因；设备界面未公开 native errno。

[RFC 4254 第 5.2 节](https://www.rfc-editor.org/rfc/rfc4254#section-5.2)
定义通道窗口与数据流，[第 5.4 节](https://www.rfc-editor.org/rfc/rfc4254#section-5.4)
定义请求和答复。允许上述顺序是对协议的兼容性解释，不意味着服务器必须提前发送数据。

## 修正边界

通道确认后，PTY／shell 答复等待期间收到的普通输出和标准错误，按原有窗口和容量
上限暂存在同一个会话。只有真实 shell 成功答复后才能读取并按到达顺序交给终端；
请求被拒绝、远端提前关闭或发生终止错误时清除未发布的数据。主机信任、认证、会话
所有权和取消／锁屏行为不因输出而放宽。

加密合成测试覆盖两个等待阶段各自成功、拒绝和提前关闭，以及确认前读取失败和成功后
顺序交付。现有 session／窗口／保活回归继续执行。不同服务器和修正版设备表现只按
实际验证报告；[本地记录](verification.md#20261116-ssh-screen-lock-and-early-output)、
[指定板复测](verification.md#20261116-ssh-early-output-device)，
[可执行契约](../.trellis/spec/backend/ssh-shell-early-output.md)。
