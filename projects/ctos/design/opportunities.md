# ctOS 产品与体验改进机会

2026-09-25 进展：可信连接快照、逐条连接 item、可得应用图标/名称及 Oplus 分身别名检索已在第一阶段实现，并在 Android 16 手机上定向检查；下表的“当前证据”保留探索时的源码状态，其余建议仍需分别实施和验收。具体验证范围见 [verification.md](verification.md)。

日期：2026-09-25。性质：基于创建时源码、规划、验证记录及 `build/ctos-*` 本地历史截图的探索建议；探索文档创建时没有构建、运行测试或连接设备。本文的优先次序是建议，不改变 [规划](plan.md) 的阶段状态。

## 判断

ctOS 已有可用的网络观测和本机终端基础，但用户旅程目前多止于“看到数据”。最高收益来自两件事：先让数据与权限状态可信、可理解，再把信息对象和只读任务连成可保存的操作流程。美化应伴随信息层级与操作效率改善。

当前工作台、信息、命令、终端均已存在；P0/P1 尚未全部验收，P2/P3 所写的历史、收藏、对象关联仍是计划。已验证设备及范围见 [验证记录](verification.md)，不把 Android 11 旧 current 包结果或 Android 16 手机的 Root 结果当作当前包跨设备完整验收。

## 工程支撑与验收

- `lib/main.dart` 同时承担采集调度、权限状态、命令结果、网络/终端页面和导出（约 1200 行）。在新增能力时先抽出快照、能力状态、任务结果三个明确模型，再按领域迁出页面状态。最小验证是现有网络速率、Root 会话、PTY 与导出回归；避免为拆文件而重写。
- Flutter 当前有 19 项测试，包含终端输入和窄屏键盘检查。新增状态模型时补有意义的状态转移测试和窄屏/大字号组件检查；实机仍需分别检查 Android 11/16、SELinux 差异、软键盘与前后台。具体未验收项见 [验证记录](verification.md)。
- 当前 APK 使用开发调试签名，属孵化阶段；真正分发前需要独立确定正式签名与升级路径，见根 [README](../README.md) 的构建说明。

## 建议顺序

1. 先完成“快照新鲜度 + 权限状态/恢复 + Android 16 受限说明”，同时收敛工作台和设备页的视觉基线。这一步让现有信息更可信，且符合 P0/P1 未完成的事实。
2. 用一个只读对象任务打通“信息 → 命令 → 结果 → 选择性导出”，再加本地历史。以端到端体验检验 P2 模型，而非先堆命令数量。
3. 根据真实使用频率扩展应用、进程、连接、日志关联；终端多会话、持续采集与远程能力留待单独设计和实机验证。

本文是方案建议，不表示这些功能已经实现或通过验收。后续每个实施切片应分别定范围和验收标准。
