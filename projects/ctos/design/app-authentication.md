## 用户已确认的统一模型

用户要求沿用 Authenticator 讨论形成统一心智模型，应用到 SSH，减少理解和维护成本；本轮取代 SSH 原“仅设备 Keystore 凭据库、不迁移”的规划。

- 第一次使用需要保存秘密的功能：设置并确认一个 App 主口令，或导入已有加密库；询问是否开启本设备生物识别/系统锁屏快捷解锁。
- 主口令经密码派生函数产生加密密钥，库始终加密落盘；使用时仅临时解密到内存，不创建明文库/临时文件。
- 用户主动开启快捷解锁后，可用系统身份验证恢复本设备解锁材料；可以关闭，关闭清理本设备包装材料和专属密钥，保留主口令加密库。
- 同一版本化加密库容纳 TOTP 种子、用户选择保存的 SSH 密码/私钥口令，以及主动导入的 SSH config、Include 文件、私钥/相关公钥或证书及主机信任记录。2026-10-09 用户确认文件一并打包保护；保护覆盖 ctOS 受管本地持久副本和加密备份，不能只加密口令/导出而留下长期明文私钥。Authenticator 与 SSH 不各自实现 KDF、库加密、设备包装、解锁或迁移流程。
- 导出为主口令保护的加密文件；另一设备输入来源主口令认证解密、预览并明确确认覆盖后提交，失败/取消保留原库。成功后旧目标解锁材料/库会话失效，新设备重新登记快捷方式。原设备 Keystore、系统锁屏秘密和生物数据不随文件导出。
- 不自动上传、不启用云同步，不自动保存所有 SSH 输入；SSH 仍可以仅当次使用。普通信息/App Shell/Root/HFTP 的既有权限行为不因统一库而自动改造。

统一秘密库并不意味着一份全 App 已认证布尔值或任意秘密读取接口。调用方仍逐次请求匹配用途/条目/目标的操作；2026-10-09 用户确认前台跨功能共用有效会话，后台保留秒数可自行选择。主口令、Android 锁屏凭证、SSH 远端密码和私钥口令是不同秘密，UI 应明确各自用途。

## 分层与所有权

```text
首次设置 / 设置页 / 加密导入导出
                  ↓
AppSecrets：统一密文库、KDF、主口令管理、设备包装、库代次、内存会话
                  ├─ AppAuthentication：系统验证/取消/并发/Keystore 受保护操作
                  ├─ TotpAdapter：TOTP 条目、代码和展示投影
                  └─ SshCredentialAdapter：目标/账号/私钥身份绑定、受管 native 通道
```

公共 Android 宿主拥有加解密、会话及类型化受保护操作；Flutter 负责交互，只获得所需条目展示信息、代码及状态，不获得主密钥/原始种子或通用秘密枚举返回。主口令输入只用于指定解锁或管理请求，输入缓存和跨平台副本尽力清理，不承诺托管运行时完全物理擦除。

统一存储条目/文件对象带 namespace、type、entryId、资源身份、逻辑相对路径及 schema；TOTP 只能管理自己的种子并产生代码，SSH adapter 管理自己的配置文件图/信任/密钥对象，并向核验后的匹配连接释放选定凭据或受管文件视图。主机别名不是密码绑定身份，私钥路径不是密钥身份。Root、SAF、SSH host key 信任和远端登录仍由各自原有规则管理。

## 文件与密钥契约

当前实现使用 [Argon2id（RFC 9106）](https://www.rfc-editor.org/rfc/rfc9106) 派生 256 位密钥、[AES-256-GCM（NIST SP 800-38D）](https://csrc.nist.gov/pubs/sp/800/38/d/final) 认证加密。v1 参数固定为 64 MiB / 3 次 / 4 lanes，16 字节随机盐、12 字节新 nonce、16 字节标签；88 字节文件头用 AAD 认证。解析前限制密文/参数，完整认证后才解析条目；格式明文上限 12 MiB、1024 条目、128 文件、每文件 1 MiB、文件总量 8 MiB、引用深度 8。算法来源见 [依赖](dependencies.md)，可执行契约见 [宿主规范](../.trellis/spec/backend/app-secrets.md)。设备性能基准仍待实测，不从 JVM 测试推定手机可用。主口令及设备包装密钥不保存于便携包，禁止 nonce 复用或静默降级。

本设备快捷材料由认证绑定的 Keystore 密钥保护，绑定库 ID、KDF 参数及代次。开启需要先口令解锁和系统登记；系统成功布尔值不能代替密码操作约束。关闭、库覆盖、口令/盐改变或失效后精确清理/重新登记；Keystore 失效只影响快捷路径，主口令仍可解密便携库。

同一主口令结合文件内各自盐/参数可解密各备份，不要求相同密文。改主口令需要重新加密本地库，旧备份仍需要旧口令；没有主口令或其他可用恢复材料时无法靠重置恢复文件。弱口令可被拿到文件后离线猜测，UI 限流不能代替 KDF 和足够强口令。

统一加密备份已确认包含 TOTP 种子、保存的 SSH 凭据及其受管 config/Include、私钥/相关公钥或证书、known_hosts 等信任记录，首版按完整受管库导出/覆盖，不额外增加分组导出的未决流程。只包含用户已主动导入 ctOS 管理范围的引用闭包，不扫描个人 ~/.ssh、外部任意路径或其他 App 数据；外部原件由用户保管，ctOS 不自动删除或声称它们已经加密。设备 Keystore/生物数据/会话不打包，本设备后台保留秒数设置不作为秘密迁移，目标设备保留自己的设置。

包内 manifest 使用逻辑相对路径、对象类型/ID、内容摘要、身份和引用图并受整体认证加密保护；不把源设备运行时绝对路径、FD 或 SAF 授权带到新设备作为可用引用。导入完整认证/校验后，SSH adapter 校验引用闭包、重复路径、遍历/绝对越界、链接/类型、缺失 Include/IdentityFile 与数量/大小/深度上限，再预览条目/文件/覆盖范围。禁止解压即执行 config；本地命令及绕过主机核验规则继续适用。明确确认后公共底座以同一代次原子提交整个包，失败/取消保留旧库、文件关联和设备快捷材料；不能恢复一半 config/密钥而另一半仍引用旧对象。

主机信任记录一起迁移，但导入预览必须单独展示来源与信任覆盖范围，由用户审阅；连接仍按实际目标/端口/指纹核验，变化指纹阻止连接。与目标已有信任冲突或回滚旧信任不得静默处理，拒绝/取消保留旧状态；加密包认证完整只证明内容未被篡改，不证明所记指纹仍代表当前远端。源设备与目标不同、缺失映射或未批准冲突时不可伪造“已全部恢复可连”。

恢复审阅同时覆盖来源和本次目标口令已认证的当前库：纯 TOTP 备份覆盖现有 SSH 库，也会移除目标的 SSH 凭据/文件/信任，必须显示这部分影响。公共核心负责有界不可变投影、完整对象覆盖核验及与来源/目标密文摘要、语义 provider 版本和注册代次绑定；SSH provider 负责实际信任变化/冲突/删除/无法映射的语义。提交必须匹配用户看到的同一审阅绑定，生产 provider 缺失时拒绝相关恢复。

### OpenSSH 使用加密文件的技术关卡

2026-10-10 实施探针：[固定 OpenSSH 宿主研究及复现](../.trellis/tasks/10-08-app-authentication/research/ssh-memory-results.md) 已通过六组真实源码检查，主会话另以新目录独立重放通过。该证据覆盖文件访问形状，尚不覆盖 Android/Bionic/16 KiB、完整登录、每跳私钥授权、库写回事务或已建立连接锁库后的行为；研究适配器不作为生产授权边界。

持久权威数据是公共库中的密文文件对象；原“稳定私有 SSH 目录”现在指稳定逻辑结构和加密受管副本，不另存普通文件形式的长期明文副本。查看/编辑 config、主机列表求值和连接均经有效公共库会话；Flutter 只获得必要的已解锁配置编辑内容/展示结果，私钥内容不默认展示。

native OpenSSH 的配置/IdentityFile/known_hosts 使用文件语义，不能凭便携加密库存在就宣称能直接读取密文。优先研究内存/匿名内存 FD 与受管 native 文件访问适配：保持 OpenSSH 的 Include/路径匹配及 ProxyJump 各跳语义，不落持久明文 staging；已确认 host key 产生的信任更新回送 host 校验后加密提交。具体是否需要 native 文件读取适配、如何支持引用目录和写回需首个探针验证；普通磁盘临时文件不是“纯内存解密”的等价实现，若探针不能满足就回规划，不能偷偷降级。

依据：[OpenSSH ssh(1)](https://man.openbsd.org/ssh) 的 -F/-i 文件入口、[ssh_config(5)](https://man.openbsd.org/ssh_config) 的 Include/IdentityFile/信任语义，以及 Android [NDK shared memory](https://developer.android.com/ndk/reference/group/memory) 和 [SharedMemory](https://developer.android.com/reference/android/os/SharedMemory) 的内存/FD 能力；后两者不证明 OpenSSH、目录引用或 ROM 上已经互操作，本轮未运行探针。

每个临时视图绑定库代次和连接/求值请求，不能交给普通 Shell/Python 或复用为任意路径读取能力；用完/失败/取消/锁库后回收。已完成远端认证的 SSH transport 可继续，而可再次加载秘密的视图/认证请求不得因此延长；native 已解析私钥及内存副本的清理效果必须验证，不承诺同 UID/Root 隔离或完全擦除。

## 管理操作与导入信任状态（2026-10-09 已确认）

用户确认导出、导入覆盖、更换主口令和关闭本设备生物/系统锁屏快捷解锁要求重新手动输入主口令，并强调输入必须用于真实解密及程序上的信任判定；生物识别或已解锁使用会话不能代替本次管理验证。不持久保存主口令或另设明文/摘要比对来冒充解密成功。

- 导出：本次输入当前库主口令，重新派生密钥并对当前代次密文完成认证解密；通过后才能导出该代次一致快照。认证失败不创建文件。2026-10-10 用户要求目标同名时提示覆盖、失败清理本次创建的部分并保护原文件；运行中取消也等待清理终态，不能仅按前端取消标记声明无文件。
- 导入：本次输入来源包主口令，针对不可变来源密文快照派生密钥并完成认证解密。已有目标库覆盖还需新输入当前目标库主口令并认证解密当前代次；界面区分来源与当前口令，不假定两者相同。新设备无现有库时只需来源口令。
- 更换主口令：重新输入当前主口令完成当前库认证解密，再设置并确认新主口令、重新加密及原子提交；失败保留旧库。成功使旧会话/设备包装失效，快捷方式重新登记；历史备份继续使用其原主口令。2026-10-09 用户确认首版包含更换主口令，入口归公共秘密库设置，覆盖全部 TOTP/SSH 条目与受管文件；只改变 ctOS 库保护口令，不改变服务 TOTP 种子、SSH 远端密码或私钥自身口令。新口令确认后使用新盐/密钥及随机 nonce 构建新密文，完成认证读回与内容一致性检查再提交。提交前失败/取消不改变旧库和快捷材料；崩溃恢复只能选完整旧代次或完整新代次，不能混用。提交后快捷重登记失败保留新密文并回退新主口令，不回滚已完成改口令或复活旧包装。已有备份不自动重写，界面明确旧备份仍用旧口令。

- 关闭快捷解锁：2026-10-09 用户确认关闭前必须本次手动输入当前主口令，派生密钥并认证解密当前代次；生物成功/已有解锁会话不代替。口令错误/取消/关闭提交前失败保留库和原快捷状态，确认后仅停用本设备公共快捷路径并清理包装材料/专属密钥，保留完整 TOTP/SSH 密文库。关闭使快捷请求/旧回调及现有库会话失效，进入锁定，随后两业务用主口令解锁；不修改 Android 系统锁屏/生物登记或其他设备。管理授权绑定库/代次和设备快捷材料版本，旧验证不能关闭已重新登记的材料。停用状态持久化先于不可逆密钥清理；提交后清理失败保持停用并有界重试清理，不重新启用旧材料，重启也不能复活旧快捷路径。忘记口令不能只靠生物成功绕过这一步，用户仍可按既有快捷状态日常使用。

框架内导入状态为：未验证 → 有界文件头/资源检查 → 认证解密成功 → schema/引用/身份/业务规则校验成功 → 预览与覆盖/信任审阅确认 → 同代次原子提交。只有后续阶段所需的受限对象可从前一阶段获得，不能由前端传入一个 trusted/已验证布尔值跳过步骤。AAD 覆盖版本/算法/参数等公共头部；认证标签验证完成前，解密器可能输出的任何字节都不得解析为业务内容、显示、执行、落盘或写入目标库。认证后的内容仍须校验路径/大小/类型及禁止执行等业务规则。

错误口令、篡改、截断或损坏导致认证解密失败时，来源仍为未验证，统一提示“口令错误或文件损坏”，不宣称可精确区分原因；拒绝采用其内容、尝试另一算法降级或部分恢复，保留目标库及设备快捷材料。超限/不支持格式先拒绝昂贵派生，格式诊断不能伪装成认证成功。来源认证成功证明该密文可由该口令派生密钥验证，不能证明发送者身份、内容新鲜性或 SSH 远端身份；信任记录仍经单独审阅及连接指纹核验。

公共宿主在实际效果边界再次检查本次管理授权，绑定 operation、来源密文摘要、目标库 ID/代次及所批准的覆盖范围；只用于一次操作。来源被替换、目标代次变化、取消/锁定/重启或迟到回调使授权失效，不能将一次输入转换为通用管理权限。预览和提交使用同一已验证快照，失败/取消清理短期输入/解密缓冲及未提交结果，不损坏旧数据。忘记主口令不能通过重置跳过包认证。

文件导出只获取本次所选目录授权，不增加广泛存储权限或持久 tree grant。先创建随机独立临时文档，写入/关闭/完整密文读回验证；覆盖确认绑定精确旧对象，旧文件仅移到随机回退名，最终文件通过创建新文档获得新 ID，绝不对原 URI 开写流。最终文件验证前失败，仅删除本次创建的对象并尝试恢复旧名；遇到竞争文件不覆盖它。最终文件验证后，旧文件清理失败仍保留新备份。provider 拒绝删除/恢复或调用效果不明时，回执显示真实阶段与文件位置；最小私有恢复记录不存口令/明文，重启不自动扫描目录，恢复需用户重新授权。

## 使用会话与系统认证契约

AppSecrets 拥有统一的 locked / unlocking / unlocked / locking / failed 状态及不透明库会话，绑定库 ID/代次、有效期与当前前台上下文，不以一个特定页面作为唯一 owner。2026-10-09 用户已确认：ctOS 前台切页面/功能共用有效会话；锁屏/手动锁立即锁；普通切后台保留时间可由用户选择秒数，默认 30 秒，0 秒表示立即锁定；进程重启从锁定开始。TOTP 与 SSH 共用一项设置，不各设宽限。

设置放在统一秘密库设置中，采用非负整数秒，提供立即锁定及可编辑秒数；具体快捷选项/合法上限在实施契约固定，不引入“永久解锁”。宿主检查类型/边界，设置可持久保存但不保存会话或秘密。用单调时间记录进入后台时刻和截止点；按实际已过时间判定，而非假定后台回调准时执行。超时回调、回前台及每次受保护操作都检查会话/代次及截止点，超过就先锁定，不能借进程暂停、改系统时钟或迟到结果延长授权。宽限内回前台沿用原有效会话，已锁定不会因调大秒数自行恢复；如后台修改超时设置，以原后台时刻重算，已经超过的新期限立即锁定，不重置计时起点。

锁定或换库拒绝新秘密操作，释放派生密钥/种子/代码缓存，取消未完成请求并丢弃旧回调。系统自有认证/文件选择器临时切换需由宿主受管流程区分，不能成为通用绕过入口；不扩大为自动后台解锁或新连接权限。

AppAuthentication 负责系统验证；原有技术约束继续适用：

| 契约 | 行为 |
| --- | --- |
| 可用性 | 方式、需安全锁屏/生物录入、暂时或永久锁定、不支持及保护级别单列。主口令路径可独立使用。 |
| 请求 | host-owned requestId、consumer、operation、resource/target、generation；提示来自受管业务。 |
| 结果 | verified / cancelled / unavailable / locked_out / foreground_required / busy / timed_out / expired / failed，不含系统锁屏密码、生物数据或业务密钥。 |
| 系统上下文 | 不透明、用途/目标/请求绑定，仅完成当前设备包装登记/解封；最长等待 120 秒，成功上下文最长 120 秒且完成/失败/取消即失效。它不等于库使用会话，也不决定库会话总时长。 |
| 并发 | 一个系统验证，新独立请求 BUSY，重复 requestId 去重并只完成一次；取消/迟到回调不能开新库或满足新请求。 |
| 效果检查 | 库会话、consumer、操作、条目与目标逐次匹配；数据密钥不返回 Flutter 或其他任意调用方。 |
| 服务 | 需要新解锁时返回 foreground_required，不后台自动拉起系统 UI；普通后台、系统自有认证/文件选择器切换分别处理。 |

API 28/29 与 30+、强生物/系统锁屏凭证、无安全锁屏及失效分开验证；弱生物成功不保证 Keystore 密钥可用。没有可用认证不得悄悄改成免验证包装。由系统验证锁屏凭证，ctOS 不采集它。
