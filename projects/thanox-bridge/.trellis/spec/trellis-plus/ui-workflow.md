# Flutter UI workflow

The product has a planned Flutter mobile UI, although concrete frontend experience is deferred and there is no UI implementation yet. Project-local Codex UUPM was initialized with `uipro init --ai codex --offline`; its entry is `.codex/skills/ui-ux-pro-max/SKILL.md`, and its search script and Flutter data are under that directory. These platform files are local and ignored, not the shared policy. In another checkout, use `uipro init --ai codex --offline` only when an installed CLI provides its bundled templates and the action is authorized, then check `python3 .codex/skills/ui-ux-pro-max/scripts/search.py --help`. If the tool or bundled templates are missing, report the setup prerequisite instead of assuming these files travel in Git. Ensure the platform directory is locally ignored; use the clone's local exclude rules when no existing ignore covers it.

For a task that actually changes user-visible UI: (1) **Plan** by reading the local UUPM instructions and researching the relevant Flutter/domain guidance; place a concise permitted research record under the task, and record approved decisions and loading/empty/error/permission states in `design.md`. (2) **Implement** only against those approved decisions and register the research, design and relevant shared details in both task contexts. (3) **Check** the changed flow, touch targets, accessibility, text scaling, states and applicable device sizes using Flutter/native Android checks; use browser automation only for an actual browser surface. (4) **Update spec** with stable, original project decisions after verification, preserving third-party attribution and avoiding duplicate design sources.

Do not generate or approve a visual design system during bootstrap, choose a state-management library based only on a UUPM search, or claim that an absent UI has been tested.
