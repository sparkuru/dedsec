# Development environment

## Current stage

The product is an Android-only Flutter application with a Kotlin platform bridge. Its application ID and Kotlin namespace are `im.majo.thanox_bridge`; its Flutter package name is `thanox_bridge`. The project root contains `pubspec.yaml`, `lib/`, `test/` and `android/`; there is no web/server preview. Separate ordinary-app probes and the product UI exercised selected Thanox CAMERA, RECORD_AUDIO and VIBRATE modes using disposable targets. The earlier phone results are in `.trellis/tasks/11-20-verify-thanox-pro-api/research/permission-device.md`; board results and limits are in `research/board-compatibility.md` and `research/same-root-device-20261125.md` under that task.

Root `./hako` runs ephemeral commands as the host UID/GID using `ghcr.io/cirruslabs/flutter:3.35.7` by default. The current environment provides Flutter 3.35.7, Dart 3.9.2, JDK 21.0.6, Android platform 35/build-tools 35.0.0, Gradle 8.12, Android Gradle plugin 8.9.1 and Kotlin plugin 2.1.0. The app compiles against and targets API 35, with minimum API 28; Thanox operations are restricted to the Android 16 / Thanox 9.1 profile and the separately verified Android 11 / Thanox 9.6 development-board profile described in `android-capabilities.md`. `flutter doctor` recognizes the Android toolchain but reports that the image's Flutter Git checkout has an unknown channel/source. Web, Linux desktop and Android Studio are not provisioned by this Android-focused wrapper.

The host needs Docker, Bash, `flock`, `sha256sum` and standard shell utilities. The first run copies Flutter and Android SDKs into ignored `.devhome/` so the host user can write caches and install additional SDK packages. The initial copies occupied about 2.2 GiB; Android NDK/CMake and Gradle dependencies downloaded by the first build increased the complete `.devhome/` to about 7.9 GiB on this host. The temporary SDK-copy container reads one image file using the supplemental root group but writes as the host UID/GID to its isolated destination; normal command containers do not add that group. `GRADLE_USER_HOME` and Java's `user.home` also point to `.devhome/`, preserving Gradle dependencies and the debug keystore between ephemeral containers. `HAKO_IMAGE` can select a different image only if it provides the SDKs at the documented image paths. The SDK copies are keyed by image reference; replacing an image under the same reference does not refresh an existing copy. Docker access still follows the active Codex sandbox and approval policy. `HAKO_NETWORK=none` disables the command container's networking; dependency or SDK installation requires network access or an already populated cache.

Use `./hako flutter pub get`, `./hako flutter analyze`, `./hako flutter test`, and `./hako flutter build apk --debug`. The Android policy tests run with `./hako sh -c 'cd android && ./gradlew :app:testDebugUnitTest --no-daemon'`. The debug APK is `build/app/outputs/flutter-apk/app-debug.apk`; release signing is not configured. Flutter regenerated the ignored Gradle wrapper when a clean project copy was built with the populated development cache. These checks and a debug build passed locally, but they do not establish real-device compatibility. No Android USB device or host ADB server is forwarded automatically. There is no product server, so `hako` publishes no ports and no `dev.sh` is provided.

## Device and source

For current device checks, start with `adb devices -l` and select the sole `product:rk3568_firefly_aioj` development board explicitly with `adb -s <serial> ...`; never use an arbitrary default device. The user identifies this board as a non-production test device and authorizes independent testing. On 2026-11-23 it reported Android 11 / API 30 and installed Thanox `9.6-prc` (`versionCode=3404474`); recheck the live version and service state before relying on this observation. The earlier `product:PLR110` phone is not the currently designated test target, and its Android 16 / Thanox 9.1 observations remain historical evidence rather than proof of board compatibility. ADB access may need the environment's normal sandbox approval; no policy here grants it.

`archive/thanox-repo` is a user-provided, ignored reference checkout of `https://github.com/Tornaco/Thanox.git`; the previously examined commit is `053888f56b8d07b964e848ce1ccb5f2b979bc969`. Its absence in a clean checkout must be reported; acquire or restore a matching reference only with the applicable network/setup authority, without overwriting an existing checkout. Do not require this ignored path as a hidden build dependency.
