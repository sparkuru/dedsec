# Security review: permission and identity boundaries

The project's general policy in `.trellis/spec/trellis-plus/validation.md` calls for targeted human review of permission changes. On 2026-11-25 the user explicitly requested an independent sub-agent security review in place of human review for this task and delegated handling its findings. That review is recorded in `security-review-agent-20261125.md`; it is an agent review, not a claim of human review, and does not change the general policy. The main agent separately smoke-tested the fixed product on the board, as recorded in `security-review-board-20261125.md`.

## Review scope

- `android/app/src/main/kotlin/im/majo/thanox_bridge/ThanoxCompatibility.kt` and `ThanoxService.kt`: the board profile requires API 30, the named board product, Thanox package/version metadata, and the observed Binder descriptor, service version and identity response. The phone profile is now also restricted to the previously observed PLR110 product and Pro package/version; that tighter path has not been physically retested on the phone. The package metadata and Binder response are checked separately; they are not cryptographic proof that the Binder comes from that installed APK.
- `PermissionPolicy.kt` and `PermissionRepository.kt`: the exact operation code, reported name, Android permission, capability flags, target SDK and non-system status gate writes. A package declaring a shared UID is read-only and is rejected by the native write path. Recheck the allowed states against the board observations and the historical phone observations rather than assuming that modes have the same effect across profiles.
- `ThanoxOps.kt`, `ThanoxPackageIdentity.kt` and the guarded write in `PermissionRepository.kt`: Android identity and the Thanox exact UID are checked around writes, but these checks and the Binder operation are not atomic. IOps and UID lookups derive from the same verified root connection per request. The inspected board APK's reached AppOps paths and UID interface call the same named cached resolver with related initial wiring; the object and cached value may change, the active Binder's provenance is unproven, and some runtime-permission actions precede that lookup. A failure after issuing a write is reported as uncertain, not as a definite rollback.
- `MainActivity.kt`: the bridge uses one background worker for requests. The inspected APK's write path includes an untimed latch wait; an actual hang has not been observed, but a stuck Binder call could block that worker. A timeout or retry cannot assume an already issued mutation was canceled.

## Evidence available for the review

- `board-compatibility.md` records separately signed ordinary-app probes, the SDK 30/35 operation and Android readback matrix, product UI tests, the shared-UID read-only UI observation and cleanup. The targets did not use physical hardware. SDK 31–34 and other board/Thanox versions were not established.
- `shared-uid-proof.md` records the observed cross-package CAMERA effect on the phone and the original real native repository rejection. `same-root-device-20261125.md` records the later opt-in runner's full board pass, controlled fake Binder checks, independent Android readback and cleanup. `uid-resolver-source-20261125.md` explains why the provided upstream source lacks the relevant implementation. `uid-resolver-bytecode-20261125.md` and `uid-dex-independent-review-20261125.md` document the separately inspected board APK and the precise limitations of that evidence.
- After the review fix, the board smoke-tested debug APK had SHA-256 `815a64fc08ea3de58306edae98506cdbbbd40e4e10cdfb8a132356ab41b78f49`. Local validation passed 33 Android unit tests, Flutter analysis and 35 Flutter tests; Android lint reported zero errors and four existing warnings. The tightened phone profile was not re-exercised on the phone.

## Review outcome and remaining limits

The agent identified and fixed the over-broad phone profile; it found no other provable high-priority defect in the reviewed scope. The explicit compatibility limits, conservative shared-UID restriction, service provenance and identity races, possible partial effects and potential indefinite wait remain part of the product's known boundaries. The user delegated handling the review results for this task.
