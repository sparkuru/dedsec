# First product feature implementation plan

1. [x] Establish the current device's Thanox `IOps` behavior with a temporary probe and separately signed disposable target; read back changes independently and clean up both apps. The target was removed after the original flags could not be exactly reconstructed; see `research/permission-device.md`.
2. [x] Generate the Android-only Flutter project using the containerized SDK and record the actual Android, Gradle and Kotlin requirements. Keep generated files limited to the product and do not replace project instructions or the root README.
3. [x] Implement the current-user package and permission reader and a narrowly scoped Kotlin Thanox bridge with version/interface checks, individual supported operations and post-write readback. The CAMERA/VIBRATE allowlist has independent probe evidence and the product UI was exercised against a dedicated target.
4. [x] Implement a searchable app list and permission detail views with distinct Android and AppOps sections, explicit errors, disabled/loading states and accessible native controls. Check the selected operation flow on the designated Android phone.
5. [x] Run focused Flutter analysis and tests, build the Android application through `./hako`, and verify the real flow on the designated device with dedicated targets. Record the exact limits and cleanup in `research/permission-device.md`.
6. [x] Bind each permission write to the package identity observed in the detail view, including signing and install/update metadata. Reject a changed or unverifiable identity; a same-UID update was exercised on the designated phone. The checks cannot make a Binder write atomic.
7. [x] Initially address incomplete installed-app enumeration by merging Android and Thanox lists, preserving exact-package lookup and revalidating targets. The product flow was tested on the designated device. This automatic merge is superseded by step 13 after an independent app-list prompt was observed.
8. [x] Verify microphone operation states using separately signed disposable apps and independent Android/AppOps readback. Enable only the verified matching states and validate the product flow on the designated phone. The target, probe and debug product were uninstalled; see `research/permission-device.md`.
9. [x] Investigate the Android catalog visibility gap with a read-only, separately signed disposable target and probe. Compare the same probe with and without an explicit target query while preserving its broad package permission; capture only counts and the dedicated target, validate cleanup, and do not claim full coverage from this experiment.
10. [x] Preserve exact-package lookup when another listed application partially matches or both list sources fail; cover collisions, stale queries and error presentation. Clear stale success on manual refresh, and report changed or missing post-write identity/state as uncertain. Verify the changed Android interface.
11. [x] Verify the installed Thanox service's exact package/user UID lookup for a dedicated present and absent target on user 0, and compare UIDs around writes. The former list-conflict cache was process-scoped and was removed with automatic dual-source merging in step 13; the remaining identity checks are non-atomic.
12. [x] Investigate the separate installed-app-list access prompt with task-owned disposable apps. The user supplied a screenshot and selected Allow after reinstall; Android enumeration then returned 567 entries and the dedicated target, versus one entry before reinstall without a user choice. Caller UID and probe version changed across that comparison. Limits and verified cleanup are recorded.
13. [x] Stop automatically merging the Thanox catalog into the Android app list, since the device exposes an independent user access decision. Explain potential device filtering without inferring its state from counts. Preserve Android exact-package lookup and Thanox per-target UID checks around operations; update focused tests and validate the product on the designated device.
14. [x] Defer the initial Android app-list query until the user explicitly starts it, with a brief explanation of the possible device prompt; retain exact-package search before list loading and explicit refresh. Tests verify no enumeration on screen creation; the user successfully selected Allow after starting the read on the designated device.
15. [ ] Complete targeted human review of the permission and identity boundaries, including non-atomic write checks and unproven server-side resolver equivalence. After these limits were explained, the user authorized an interim commit on 2026-11-23; the review remains pending before task closure. Version/ROM coverage and other operations remain unverified.

Supplementary validation: Android `lintDebug` passes with a documented, declaration-local exception for `QUERY_ALL_PACKAGES` and four remaining warnings. The final APK was rebuilt after that lint-only manifest annotation; the device-tested build and comparison limits are recorded in `research/permission-device.md`.
