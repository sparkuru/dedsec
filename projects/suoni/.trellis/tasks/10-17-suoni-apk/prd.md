# Suoni APK 设备控制方案

## Goal

实现独立的 Suoni Android APK，让用户管理和控制自己的 Sony 设备。以 archive 中 Sound Connect 协议分析与原型为依据，提取必要的设备管理行为并独立实现。

状态：planning，方案初稿。2026-10-17 用户已授权创建 task 和规划；尚未确认首版范围，也未授权进入实现。

## Background and Confirmed Facts

- Kotlin 和 Flask 是已有项目方向。2026-10-17 用户确认：Android/Kotlin 持有蓝牙连接并独立控制设备；Flask 仅用于开发模拟与回归验证，基本控制必须离线可用。
- 参考资料包含 Sound Connect APK、协议报告、Python 控制工具与 Kotlin 原型；新应用尚无活动源码/build root。
- 报告记录 WF-1000XM4（v2，固件 2.3.1）、WF-1000XM6（v2，1.6.0）和 WH-1000XM4（v1，3.0.1）的历史实测。这些是候选验证对象，不表示本次可访问硬件或已支持机型。
- 证据与限制见 [资料研究](research/reference-assessment.md)。

## Requirements

- R1：交付可安装的 APK；实际验收型号、固件和手机 Android 版本需明确。
- R2：参考 archive 实现自己的设备控制逻辑，保留原资料；Sony APK 不进入新应用资源或依赖。
- R3（建议首版）：用户从系统已配对设备选择一个目标；显示连接状态、型号、固件、协议版本和可用电量。
- R4（建议首版）：降噪 / 环境声 / 关闭切换，按设备能力提供环境声档位与人声模式；设备不支持的功能清晰标示。
- R5（建议首版）：外部按键引起的状态变化及时反映；写入后经设备响应、通知或回读确认，失败不显示成功。
- R6（建议首版）：拒绝权限、蓝牙关闭、无设备、断连、超时和不支持均有可理解状态与恢复入口。
- R7（已确认）：基本功能离线可用，不依赖 Sony App、Sony 账号或 Flask 在线；Flask 不进入 APK 运行时控制链路。

## Proposed Out of Scope

首版暂不含 EQ、播放/音量控制、DSEE、多点连接管理、按键映射、语音提示配置、快捷磁贴、后台常驻、BLE GATT、自适应声音控制、固件升级、云账号、Web 管理界面、商店发布或所有 Sony 型号兼容承诺。后续按设备能力逐项规划。

## Acceptance Criteria

- [ ] AC1 → R1/R2：在约定手机安装并打开 Suoni APK；构建不依赖 archive 中的 APK/原型工程。
- [ ] AC2 → R3/R6：授权后选中已配对目标并读取真实设备信息、电量；拒绝权限、蓝牙关闭、无设备有明确提示；未知电量不显示为 0%。
- [ ] AC3 → R4/R5：真机完成降噪 → 环境声 → 关闭 → 降噪，响应/通知/回读与设备实际状态一致；只呈现该设备支持的选项。
- [ ] AC4 → R4：在支持时调节环境声档位/人声设置，验证范围来自设备且无关字段保留。
- [ ] AC5 → R5/R6：耳机侧切换后页面更新；断连后显示离线并可重新连接；超时不会伪装成功，不盲目重放结果不明的写入。
- [ ] AC6 → R7：关闭手机互联网、停止 Flask、退出 Sony App 后，AC2–AC4 仍通过。
- [ ] AC7 → R1/R5/R6：协议固定字节样本、会话异常测试、构建/lint 与原生 UI 检查通过；真机结果单独记录，不能以模拟器代替。

AC6 的离线与独立运行要求已确认；其中依赖 AC2–AC4 的具体操作随首版范围收敛。其余验收细节仍为建议；所有验收均未执行。

## Blocking Product Decisions

1. 首个验收耳机型号/固件、手机 Android 版本；其余设备的优先级。
2. 首版功能是否采用 R3–R6；系统配对、前台使用和单活动目标是否满足用途。
3. Android 最低支持版本、应用标识及 UI 技术/交互方向。先确认功能与设备，再逐项收敛。
